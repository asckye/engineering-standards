# <a id="pc"></a>领域 C：工程软件自动化（厂商 API）

> **要点** 厂商 API 关在适配层或独立进程；按精确 SDK 编译；功能按版本登记，不推断。

适用于经厂商 API（COM 或 .NET，例如 PLC 编程软件、电气 CAD 的开放接口）驱动另一款工程软件的工具。常与领域 A 一起使用。

## <a id="pc-isolation"></a>C.1 隔离与线程

- **MUST** `VND-01` 厂商 API 只在适配层出现，最好在独立的 worker 进程中；厂商对象不跨请求持有、不跨进程传递，按名称或规范路径寻址。
  - 理由 · 跨请求持有厂商对象会导致崩溃或误操作。
- **MUST** `VND-02` 按厂商文档使用指定的线程与单元（STA 或 MTA）；调用前核对，不符时在调用前拒绝；适配器不用 `Task.Run`、`ConfigureAwait` 或调度器把原生调用挪到其他线程。
  - 理由 · 在错误的线程上调用会让目标软件崩溃或挂起。
- **MUST** `VND-03` 插件运行在目标软件进程内时：经统一的调度器在主线程上执行，调度带超时（不用没有超时的同步调度）；调度的委托内部捕获全部异常；有模态对话框打开时拒绝并报“忙”；主线程上不 `await`、不阻塞等待其他线程。
  - 理由 · 未捕获的异常会结束目标软件进程。

## <a id="pc-versions"></a>C.2 版本与注册

- **MUST** `VND-06` 每个支持的目标版本按其精确 SDK 编译适配器；构建核对引用的版本，不符就失败，不静默回退到本机的其他版本；厂商程序集不复制、不分发（DEP-07）。
  - 理由 · 静默回退到其他版本会产生难以复现的缺陷。
- **SHOULD** `VND-07` “功能 × 目标版本”的支持关系只在一张登记表中声明，注册、发现、文档、示例和测试共用；编译期差异只用一份特性符号表表达。
- **SHOULD** `VND-08` 各版本的功能数量随 API 支持而定，不为一致而拉平，由生成目录给出。

## <a id="pc-writes"></a>C.3 写入与厂商行为

- **MUST** `VND-09` 厂商提供事务或撤销时，每次写入放在一个事务内并合并为一个可撤销步骤（标注来源，如 “AI: \<tool>”）；读回校验通过才提交，其余路径回滚。
  - 理由 · 半途失败会留下损坏的项目。
- **SHOULD** `VND-10` 操作前后收集目标软件的系统消息差异，把相关消息随结果返回；很多失败只出现在这里。
- **MUST** `VND-11` 用禁用 API 列表拦住“看似读取、实际写入”、占用许可或已知会使目标软件崩溃的成员；确需使用时就地抑制并写明原因。
  - 理由 · 看似读取的成员可能写入项目或占用许可。
- **SHOULD** `VND-12` 自动化代码不弹出界面（除审批外），在目标软件的静默模式下执行；检查许可时不占用许可。
- **SHOULD** `VND-13` 每条依赖的厂商行为记在 API 笔记中（编号、版本、验证日期），代码注释引用编号（P-01、CMT-02）。

## <a id="pc-checklist"></a>C.4 新增目标版本清单

- [ ] 取得该版本的 SDK 与文档，放在本机，不入库。
- [ ] 在版本登记表中加一行，并在特性符号表中声明差异。
- [ ] 按精确 SDK 编译适配器；构建核对版本。
- [ ] 逐个功能核对 API 证据，生成目录和数量；不支持的动作返回“不支持”。
- [ ] 示例按该版本 schema 生成；离线检查通过。
- [ ] 实机核对清单加入该版本；台账先标 `NOT RUN`，验证后更新；支持矩阵与发布说明同步。
