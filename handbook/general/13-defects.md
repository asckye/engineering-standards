# <a id="bugs"></a>13 缺陷处理

> **要点** 先归类、再定位、再修；每个修复带一个修复前失败的测试，同一缺陷不会回来。

## <a id="bugs-triage"></a>13.1 分级

| 级别 | 定义 | 响应 |
|---|---|---|
| S1 | 损坏用户数据、未经确认写入目标或设备、可能影响人员或设备安全 | 立即用配置停用相关功能，修复，[M+] 写不追责的复盘 |
| S2 | 结果错误但没有写入 | 下一个修订版本 |
| S3 | 体验、文字、性能问题 | 常规排期 |

- **SHOULD** `BUG-01` 缺陷当天登记：复现步骤、版本、环境（目标版本、操作系统）、证据。
- **MUST** `BUG-02` 每个修复带一个修复前失败、修复后通过的回归测试；做不到时写明原因（例如只能实机复现）并加入实机核对清单。
  - 理由 · 没有回归测试，同一缺陷会再次出现。
- **SHOULD** `BUG-03` 失败先归类再行动：真实缺陷、不稳定测试、环境问题、本分支引入的回归。
- **MUST** `BUG-04` 先定位根因再修；不靠反复重跑和试错。
  - 理由 · 试错修复会引入新缺陷并浪费轮次。
- **MUST** `BUG-05` 不稳定的测试：保留证据，找原因修好；隔离（quarantine）只经维护者批准，带 Issue 和期限；不“重跑到通过”。
  - 理由 · 重跑到通过会掩盖真实的竞态缺陷。
- **SHOULD** `BUG-06` [M+] S1 复盘写入 `docs/postmortems/`：时间线、影响、根因、为什么防线没拦住、行动项（落到 Issue）。
