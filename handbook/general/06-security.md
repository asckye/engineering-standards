# <a id="security"></a>6 安全

> **要点** 威胁集中在审批绕过、路径穿越、XXE、命令注入、本机认证、密钥泄露和提示注入。安全流程按等级取舍。

## <a id="security-scope"></a>6.1 范围与信任边界

- **SHOULD** `SEC-01` [M+] 威胁模型文档：资产、信任边界、STRIDE 威胁、措施及其测试、已知缺口，并写明前提与范围外的情况（例如“同一 Windows 用户”是信任边界）。

## <a id="security-approval"></a>6.2 确认与审批不可绕过

- **MUST** `SEC-03` 需要人确认的操作，确认只来自人独立操作的界面（独立的审批窗口、目标软件内的对话框、操作员终端）；调用方的参数、元数据、批处理或客户端自己显示的表单都不能代替。
  - 理由 · 客户端能自己批准写入就等于没有审批。
- **MUST** `SEC-04` 确认请求号由服务端生成；决定绑定请求号、计划指纹和去敏后的参数摘要，只能使用一次；迟到、重复、不匹配或格式错误的决定一律按拒绝处理。
  - 理由 · 防止伪造、重放或张冠李戴的审批决定。
- **MUST** `SEC-05` 确认开关、可写范围等安全配置只能由人在配置文件或“仅人可改”的设置页修改；没有接口或工具能修改它们，也不能写这些文件（包括经短文件名、链接或文件 ID 的写法）。
  - 理由 · 防止自动化或 AI 关掉自己的保护。
- **SHOULD** `SEC-06` 确认关闭时，每个执行结果带“确认已关闭”的警告，界面持续显示该状态，开关变化写入审计。

## <a id="security-path"></a>6.3 路径穿越与压缩包

- **MUST** `SEC-07` 外部给出的路径只接受固定根目录之下的相对路径：拒绝绝对路径、UNC、驱动器号、`.`、`..`、空段、控制字符、Windows 保留字符和保留设备名（`CON`、`NUL`…）；按规范化后的完整路径判断。
  - 理由 · 防止写到预期目录之外。
- **SHOULD** `SEC-08` 根目录之下的每一级都不能是符号链接、联接点或其他重解析点；写出后再列出目录，确认文件都在根目录内。
- **SHOULD** `SEC-09` 导出和输出写入每次新建的空目录，从不覆盖已有文件，除非调用显式允许覆盖且经确认。
- **MUST** `SEC-10` 压缩包在内存或新建的临时目录中读取：条目名按 SEC-07 校验，名称忽略大小写后唯一，拒绝链接条目；文件数、单文件大小、总大小、压缩比都有上限；不执行包内任何代码。
  - 理由 · 防止压缩炸弹和经压缩包的路径穿越。

## <a id="security-xxe"></a>6.4 XXE 与解析器

规则见 [`CODE-07`](03-code.md#code)。

## <a id="security-cmd"></a>6.5 命令注入

- **MUST** `SEC-12` 启动子进程只用 `ProcessStartInfo.ArgumentList` 或 stdin 传参，`UseShellExecute=false`，可执行文件用绝对路径，工作目录为绝对路径；限制超时和输出大小。
  - 理由 · 防止命令注入。
- **SHOULD** `SEC-13` 需要执行外部命令、脚本或宏时，只执行随产品发布的白名单条目；参数逐个校验类型、枚举、范围、长度和字符集，拒绝引号和控制字符；没有工具、配置或数据文件能增改白名单。

## <a id="security-ipc"></a>6.6 本机管道与 HTTP

- **MUST** `SEC-14` 命名管道：名称由当前用户 SID 和安装路径派生；受保护的 DACL 只授予当前用户；拒绝远程客户端；双方核对对方 SID，需要时核对对方映像路径；帧有大小上限，未知字段和重复字段拒绝。
  - 理由 · 防止同机其他用户或进程冒充对端。
- **SHOULD** `SEC-15` HTTP 默认只监听 `127.0.0.1`；局域网访问只绑定人选择的具体 IP，防火墙只放行指定来源；明文 HTTP 只在私有网络中使用，作为剩余风险写入威胁模型。
- **MUST** `SEC-16` HTTP 认证：每个请求带 `Authorization: Bearer`，密钥至少 24 字节随机数，定长比较；失败只回 401，同一来源连续失败后限流；健康检查端点只返回版本等非敏感信息。
  - 理由 · 防止未认证的网络访问。
- **MUST** `SEC-17` 校验 `Origin` 头（不在允许列表中回 403，允许列表默认空）和 `Host` 头，防 DNS 重绑定。
  - 理由 · 防止 DNS 重绑定攻击本机服务。

## <a id="security-secrets"></a>6.7 密钥与凭据

- **MUST** `SEC-19` 密钥和凭据只存在受保护的用户存储中（DPAPI CurrentUser 或 Windows 凭据管理器），不写入明文配置、命令行参数（会进入进程列表）或日志。
  - 理由 · 明文密钥会经配置、进程列表或日志泄露。
- **MUST** `SEC-20` 去敏规则统一一处实现：键名含 password、passwd、secret、token、credential、authorization，或以 key 结尾（明确的白名单除外）的值替换为固定占位符；自由文本中的 Bearer/Basic 令牌、`name=value` 形式的密钥、URL 用户信息、PEM 私钥清除。审批摘要、哈希、审计和日志都在去敏后计算。
  - 理由 · 防止凭据进入日志、摘要和响应。
- **SHOULD** `SEC-21` 新增带凭据的参数时，命名符合 SEC-20 的规则，并加测试证明值不进入确认摘要、审计、日志和响应。
- **MUST NOT** `SEC-22` 在仓库、文档、夹具、截图、Issue 中出现真实凭据、机器地址、客户项目或许可证信息。
  - 理由 · 提交过的密钥只能轮换，无法真正撤回。

## <a id="security-injection"></a>6.8 经项目数据的提示注入

- **MUST** `SEC-23` 来自用户项目或设备的自由文本（注释、属性值、标签名、导入文件内容）只作为数据返回，放在数据字段中，不拼进给模型的说明或摘要。
  - 理由 · 防止项目数据中的文字被模型当成指令执行。
- **SHOULD** `SEC-24` 这类文本剥除控制字符（保留换行和制表符）和双向文本控制符（U+202A–202E、U+2066–2069），超长时截断并注明原始长度。

## <a id="security-privilege"></a>6.9 最小权限

- **SHOULD** `SEC-26` 产品以普通用户权限运行和安装；只有确实需要的步骤（防火墙规则、URL ACL、加入厂商要求的用户组）单独提权，并向人说明原因。
- **SHOULD** `SEC-27` CI 工作流令牌默认只读（`contents: read`），需要写权限的作业单独授予。

## <a id="security-sdl"></a>6.10 安全开发流程（SDL-lite）

- **SHOULD** `SEC-28` [M+] 威胁建模（只对跨越信任边界的功能）：新功能或新接口（新端点、新管道、新文件入口、新设备写入路径）在设计说明（[18.3](18-process-review-git.md#review-rfc)）中附一段简短威胁模型：画出信任边界，对每个边界按 STRIDE 列出威胁和措施；更新项目的威胁模型文档。
- **SHOULD** `SEC-29` 安全静态分析：启用 .NET 安全相关规则（CA2100、CA2300–CA2330、CA3001–CA3012、CA3075、CA3077、CA5350–CA5403 等）为警告；新增违规阻止合并。
- **SHOULD** `SEC-30` [M+] 依赖漏洞扫描：每次合并和每周运行 `dotnet list package --vulnerable --include-transitive`（或等效工具）；高危漏洞阻止发布。更新政策：高危 7 天内升级或给出缓解，中危下一个次版本处理，其余随常规更新。
- **SHOULD** `SEC-31` 密钥扫描：仓库启用密钥扫描（托管平台的 secret scanning 或提交前钩子）；发现泄露立即轮换，再从历史中清除。
- **SHOULD** `SEC-32` [M+] 发布前安全复核：对照威胁模型核对本版新增的边界和措施、去敏测试、依赖扫描结果；结论写入发布记录。
- **SHOULD** `SEC-33` [L] 或网络暴露：网络暴露模式（HTTP 等）在首次发布和每次改动认证、绑定或路由时做滥用测试：无密钥、错误密钥、暴力尝试、错误 Origin/Host、超大请求、畸形帧、跨会话访问句柄。
- **SHOULD** `SEC-34` [M+] 漏洞受理：仓库有 `SECURITY.md`（报告渠道、受理范围、响应时限）；收到报告 3 个工作日内确认并分级，高危 30 天内修复或发布缓解，修复后发布安全公告并在 CHANGELOG 中注明；事件处理按 [13.1](13-defects.md#bugs-triage) 的 S1 流程。
