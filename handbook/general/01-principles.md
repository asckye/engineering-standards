# <a id="principles"></a>1 工程原则

> **要点** 正确与安全排在简单前面，简单排在其他一切前面。只在边界校验一次；推测性抽象和防御层让每次改动都更慢。

## <a id="principles-correct"></a>1.1 正确与安全

- **MUST** `P-01` 依赖的每条目标行为都有出处（厂商文档、SDK 元数据、设备手册或实机验证记录的条目编号），不按名称、相邻版本或“应该也行”推断能力。没有出处就先验证。
  - 理由 · 凭记忆或推断写的厂商行为是最常见的实机缺陷。
- **MUST** `P-03` 未经实机验证的行为在台账和发布说明中标为 `NOT RUN`。
  - 理由 · 防止发布说明声称没有验证过的能力。
- **MUST** `P-04` 改变目标、设备或用户数据的操作先预览，再经人确认执行。
  - 理由 · 未经确认的写入可能损坏用户数据或设备状态。
- **MUST** `P-05` 失败不留下不一致的数据：能回滚就回滚，不能就先备份并如实报告。
  - 理由 · 半途失败会留下无法使用的数据。
- **MUST NOT** `P-06` 用软件代替安全功能（安全 PLC、硬接线联锁，见领域 B）。
  - 理由 · 软件故障不能危及人员与设备。

## <a id="principles-simple"></a>1.2 简单与一致

- **SHOULD** `P-08` 同一概念全项目一个名称、一种形式（参数、错误码、单位、目录、日志字段）。
- **MUST** `P-09` 同一能力一个实现，共享逻辑不复制。
  - 理由 · 两份实现迟早不一致，修一处漏一处。
- **SHOULD** `P-10` 扩展点只开在已经发生过或路线图写明的变化方向（新工具、目标新版本、新设备协议），形式是“声明式登记 + 一处实现”（2.5）；其他方向不预留，除非有 ADR。
- **SHOULD NOT** `P-11` 为跨项目复用建共享库；需要时复制并注明来源。

## <a id="principles-boundary"></a>1.3 只在系统边界校验一次

边界有四类：外部输入（API 调用、操作员输入、命令行、配置）、进程与通道（子进程、插件、设备通信）、文件与操作系统、厂商 API。

- **MUST** `P-21` 输入在跨过的边界上校验一次（类型、必填、枚举、范围、单位、路径），结果是类型化对象。
  - 理由 · 未校验的输入在深处才失败，难以定位。
- **MUST NOT** `P-22` 在内部调用中重复同样的检查；内部前提被破坏是缺陷，用断言暴露。
  - 理由 · 重复检查彼此不一致，改动时容易漏改。
- **SHOULD** `P-23` 厂商 API 或设备的返回值（空对象、未设置、部分成功、质量位）在适配层检查一次，再转为本项目的类型。

**推荐：边界一次，内部信任**

```csharp
var request = ExportRequest.Bind(arguments); // 失败 -> INVALID_ARGUMENT
return exporter.Export(request);             // 内部不再检查
```

**避免：层层重复、吞掉原因**

```csharp
if (string.IsNullOrWhiteSpace(path)) return Fail("path");
try { return adapter.Export(path ?? "", dir ?? ""); }
catch (Exception) { return Fail("unknown"); }
```

## <a id="principles-overeng"></a>1.4 不过度设计、不过度防御

- **MUST NOT** `P-12` 只有一个实现的接口或抽象类，除非它是真实边界（厂商 API、设备、文件系统、时钟、进程、网络）或测试需要的接缝。
  - 理由 · 多余的抽象增加每次阅读和修改的成本。
- **MUST NOT** `P-13` 只重抛、或记录后继续的 try/catch；“以防万一”的回退路径；每层都判空。
  - 理由 · 吞掉或绕开的错误让故障无法诊断。
- **SHOULD NOT** `P-15` 没人要求的配置项和开关。
- **SHOULD NOT** `P-16` 测试不可能出现的状态（类型系统或边界校验已排除的情况）。
- **SHOULD NOT** `P-18` 与当前问题无关的实验：计时探针、几十次压力重跑、额外的“加固轮”。只查阻塞合并或发布的问题，修好就停。

> **理由** 防御层和推测性抽象让每次改动都变慢；保护数据和设备的检查属于安全，不在此列。

## <a id="principles-truth"></a>1.5 事实只有一个来源

- **MUST** `P-25` 对外契约（API、工具、文件格式、PLC 接口数据块）只按版本政策改变（[第 17 节](17-compatibility.md#compat)）。
  - 理由 · 契约悄悄变化会让客户端失效。
- **SHOULD** `P-26` 目录、矩阵、数量、示例和迁移表由生成器从同一来源产出，生成文档开头注明生成命令且不含时间戳；手写文档只链接。
- **MUST** `P-14` 每个操作有请求号，从入口传到子进程、插件和通信层；对外报告的失败带能定位日志的诊断编号。
  - 理由 · 没有请求号就无法从报错追到原因。
