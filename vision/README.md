# 视觉软件

> **要点** 视觉软件的结果常常直接决定产品去留。指标要事先写明，每个判定都能追溯，算法或配方一变就用回归图像集重新验证。

状态：**草稿 0.1**。这里的规则都是建议，还没有项目验证过。本文件只用 SHOULD，等项目验证后再定哪些升为 MUST。

**适用：** 用工业相机做检测、测量、定位或识别的软件。只显示实时画面、不做判定的软件不适用。

**同时采用：** [通用规范](../general/README.md)和[桌面与本机软件](../desktop/README.md)；要和 PLC 通信或供操作员操作时，再加[上位机规范](../hmi/README.md)。

## <a id="vis-metrics"></a>指标与验收

- **SHOULD** `VIS-01` 开工前写明验收指标：节拍、漏检率、误检率、测量精度或重复性，以及它们在什么产品和光照条件下成立。
- **SHOULD** `VIS-02` 漏检和误检分开统计，目标由工艺负责人确认，并写明各自的代价。
- **SHOULD** `VIS-03` 测量类功能做重复性和再现性评估（例如 Gage R&R）。
- **SHOULD** `VIS-28` 通过与不通过的判定做一致性评估，写明样本量和置信度。少量样本上的“零漏检”不算证明。

## <a id="vis-trace"></a>结果可追溯

- **SHOULD** `VIS-04` 每个判定结果记录：时间（UTC）、产品或批次标识、算法版本、模型版本、配方版本、标定版本、结果和原因。
- **SHOULD** `VIS-05` NG 图像和抽样的 OK 图像按配方保存，能从结果找到原图。图像无损归档，有保留期和磁盘保护（`DAT-05`、`IND-34`）。存到机器之外时按 `DAT-06` 写 ADR。

## <a id="vis-regression"></a>回归图像集

- **SHOULD** `VIS-06` 维护带真值的回归图像集，覆盖典型 OK、各类 NG、边界样本和干扰（光照变化、脏污、位置偏移）。
- **SHOULD** `VIS-07` 算法、模型或配方变化后运行回归，漏检率和误检率作为门禁阈值。放宽阈值由维护者批准（`G-06`）。
- **SHOULD** `VIS-08` 客户图像不进仓库（`DAT-07`），放在受控存储中。仓库只放脱敏或合成的样本，并记录图像集版本。

## <a id="vis-isolation"></a>相机与算法库

- **SHOULD** `VIS-09` 相机 SDK、视觉库和推理运行库只在适配层出现（`ARC-01`）。可能挂起或崩溃的原生库放进隔离单元（`ARC-04`）。
- **SHOULD** `VIS-10` 相机接口优先用标准（GenICam 编程接口，GigE Vision、USB3 Vision 传输），业务逻辑不依赖某一品牌的相机。
- **SHOULD** `VIS-11` 提供离线回放模式：用图像序列代替相机，不连相机也能跑完整流程和测试（`TST-06`）。回放状态在界面上醒目标出。
- **SHOULD** `VIS-12` 商业视觉库和推理运行库按 `DEP-02` 写 ADR，按 `DEP-07` 不分发，除非许可证允许。运行授权缺失时启动就报错，不在半途失败。

## <a id="vis-pipeline"></a>帧管道与性能

- **SHOULD** `VIS-13` 采集、处理和输出分开，用有界队列连接。队列满时按配置丢帧或拒绝，并计数报警，不无限堆积。丢帧的产品按 `VIS-20` 判定。
- **SHOULD** `VIS-14` 图像和原生缓冲区有明确的所有者和释放点。浸泡测试监控非托管内存和句柄（`IND-32`）。
- **SHOULD** `VIS-15` 节拍是正确性的一部分：从触发到结果全程计时，按最坏情况设预算，超时按 `VIS-20` 处理。在真实相机和负载下验收，默认测试不依赖相机（`TST-06`）。
- **SHOULD** `VIS-16` 界面显示不阻塞处理，预览图可以降采样或跳帧。
- **SHOULD** `VIS-27` 图像和产品能对应：优先用硬件触发，触发时绑定产品标识，用 PLC 或编码器计数核对漏触发；统计相机丢包，网络相机用专用网卡。

## <a id="vis-recipe"></a>标定、配方与环境

- **SHOULD** `VIS-17` 标定有版本、日期和有效期。更换镜头、相机或工位后要求重新标定；过期后怎么处理由工艺负责人定。
- **SHOULD** `VIS-18` 配方按产品管理，有版本，可以备份和恢复（`IND-40`），包括曝光、增益、ROI、触发延时、镜头和光源设置；关闭相机的自动曝光和自动增益。修改配方经权限控制并写审计（`IND-26`、`IND-27`）。
- **SHOULD** `VIS-19` 定期用标准件核对系统状态，让光源老化和镜头脏污能被发现。
- **SHOULD** `VIS-29` 定位和测量结果写明坐标系和不确定度；手眼标定定期核对。

## <a id="vis-faults"></a>判定与故障

- **SHOULD** `VIS-20` 超时、丢帧、相机断线和算法异常时的判定动作（判 NG、停线或复检）事先定义，由工艺负责人确认，不默认判 OK。
- **SHOULD** `VIS-21` 把结果写给 PLC 时有超时和握手（`IND-05`、`IND-16`），结果未知时不自动重发（`IND-17`）。
- **SHOULD** `VIS-22` 视觉结果不执行安全功能（`IND-01`）。
- **SHOULD** `VIS-23` 人工复判的结果另行记录，用于改进样本，不静默修改原结果。

## <a id="vis-models"></a>模型（使用深度学习时）

- **SHOULD** `VIS-24` 模型带版本和训练数据清单，能追溯到数据集和训练配置。
- **SHOULD** `VIS-25` 新模型先用保留图像集验证或影子运行，再上线；能回滚到上一版本。
- **SHOULD** `VIS-30` 训练集和验证集按批次划分，防止数据泄漏；生产中监控模型漂移；固定推理运行库和 GPU 驱动的版本。
- **SHOULD** `VIS-26` 模型文件按外部数据处理：不用不安全的反序列化加载（`CODE-07`），来源和许可证经核对（`DEP-02`）。

## <a id="vis-checklist"></a>发布清单

- [ ] 验收指标在真实产品和光照下测过，结果已记录。
- [ ] 回归图像集通过，漏检率和误检率不高于门禁。
- [ ] 离线回放能跑完整流程；相机断线和算法异常时的判定动作已实测。
- [ ] 标定和配方可以备份、恢复，版本写入判定结果。
- [ ] 浸泡测试通过，内存、句柄和丢帧计数平稳。
