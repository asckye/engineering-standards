# 视觉软件

> **要点** 视觉软件的结果常常直接决定产品去留。指标要事先写明，每个判定都能追溯，算法或配方一变就用回归图像集重新验证。

状态：**草稿 0.2**。还没有用项目从零验证过。草稿阶段级别还可能调整，不按 [G-07](../general/00-purpose.md#purpose-gov) 升主版本。

**适用：** 用工业相机做检测、测量、定位或识别的软件。只显示实时画面、不做判定的软件不适用。

**同时采用：** [通用规范](../general/README.md)和[桌面与本机软件](../desktop/README.md)；要和 PLC 通信或供操作员操作时，再加[上位机规范](../hmi/README.md)。

节拍内把判定结果写给 PLC、换型时把配方参数写给相机，是上线前由工艺负责人确认过的自动动作，不逐次预览和确认，`P-04`、`SEC-03` 不适用于这两类写入。这两类写入结果未知时不按 `ERR-08` 锁定设备，改按 `VIS-20`、`VIS-21` 处理，`ERR-10` 的不重放仍然适用。视觉软件只送结果，不直接下发运动命令，动作由 PLC 或机器人控制器决定，`IND-17` 后半句不适用于判定结果。

**等级：** 判定会决定产品去留或驱动机构的视觉软件至少按 M 级；7×24 运行的产线系统通常是 L 级，`IND-32` 的浸泡时间按此取。

**上线：** 验收和交付按[通用规范第 27 节](../general/27-acceptance-delivery.md#accept)；和 PLC 通信时再按[上位机规范 B.13](../hmi/README.md#pb-acceptance)。现场验收在实际工位、光照和节拍下进行（`VIS-01`、`VIS-28`）。

## 级别怎么定

本规范是标准，项目遵守它。级别按违反规则的后果定，不看现有项目做到了多少。

**MUST** 用于违反后会直接出现下面任一后果、而且没有另一条 MUST 已经挡住的规则：

- 不良品被放行，或者判定出错却没有人发现；
- 判定无法追溯，出了质量问题查不到当时的版本和图像；
- 机构或机器人按错误的结果动作；
- 软件崩溃、挂起或赶不上节拍，产线受影响；
- 客户图像泄露，或者违反许可证；
- 对外声称了没有验证过的指标。

**SHOULD** 用于其余规则。

`MUST`、`SHOULD` 的含义和优先级与[工程开发规范 0.3](../general/00-purpose.md#purpose-read) 相同。

## <a id="vis-metrics"></a>指标与验收

- **MUST** `VIS-01` 正式开发前（可行性评估可以先做）写明验收指标：节拍、漏检率、误检率，测量类还有精度和重复性，以及它们在什么产品和光照条件下成立。
  - 理由 · 没有事先写明的指标，就无法判断系统能不能上线，事后也说不清漏检是否在允许范围内。
- **MUST** `VIS-02` 漏检和误检分开统计，目标由工艺负责人按两者各自的代价确认。
  - 理由 · 合在一起的准确率会掩盖漏检，而漏检的代价通常高得多。
- **MUST** `VIS-03` 测量类功能评估偏倚（对可溯源的标准件）和重复性、再现性（例如 Gage R&R）。自动测量没有操作员影响时，再现性按重新上料、工位和换型的差异评估。
  - 理由 · 测量系统的误差接近公差时，判定结果没有意义，而且从结果上看不出来。
- **MUST** `VIS-28` 通过与不通过的判定用已知真值的实物做一致性评估，同一件实物重复上料，不只重跑存图。漏检率按不良样本数给出置信上限，写明样本量和置信度；n 个不良样本零漏检，95% 置信上限约为 3/n。样本证明不到目标时，写明实际证明到的上限，不声称目标已达到。
  - 理由 · 少量样本上的好结果可能只是运气，却会被当成指标达标。

## <a id="vis-trace"></a>结果可追溯

- **MUST** `VIS-04` 每个判定结果记录：时间（UTC）、产品或批次标识、算法版本、模型版本、配方版本、标定版本、结果和原因。
  - 理由 · 出了质量问题时，查不到当时的版本和结果，就无法确定影响范围。
- **MUST** `VIS-05` NG 图像按配方保存，能从结果找到原图。图像无损归档，有保留期和磁盘保护（`DAT-05`、`IND-34`）：磁盘将满时报警，不提前删除保留期内的图像。图像或判定结果存到机器之外时经客户同意（`DAT-06`），并写 ADR。
  - 理由 · 没有原图就无法复核判定，磁盘写满还会让检测停下来。
- **MUST** `VIS-33` OK 图像的保存策略（抽样比例或滚动保留时长）由工艺负责人确认并写明，默认抽样保存，用来查漏检和补充回归图像集。
  - 理由 · 漏检的产品判的就是 OK；一张 OK 图都不留，出了问题就没有图像可查。

## <a id="vis-regression"></a>回归图像集

- **MUST** `VIS-06` 维护带真值的回归图像集，覆盖典型 OK、各类 NG、边界样本和干扰（光照变化、脏污、位置偏移）。
  - 理由 · 没有带真值的图像集，就无法证明改动没有让漏检变多。
- **MUST** `VIS-07` 算法、模型或配方变化后运行回归，漏检率和误检率作为门禁阈值。曝光、增益、光源、镜头这类成像参数变化后，已有图像不再代表新条件，改用标准件和实物核对（`VIS-19`），并补充图像集。放宽阈值由维护者批准（`G-06`），并经工艺负责人确认（`VIS-02`）。
  - 理由 · 算法、模型或配方一变，漏检率可能升高，只有回归能发现。
- **MUST** `VIS-08` 客户图像不进仓库（`DAT-07`），放在有访问控制和访问记录的存储中，这样的回归图像集不算 `DAT-07`、`SEC-22` 所说的夹具；用客户图像做回归或训练前有客户同意。仓库只放脱敏或合成的样本，并记录图像集版本。
  - 理由 · 客户图像可能含未公开的产品信息，进了 Git 历史就很难清除。

## <a id="vis-isolation"></a>相机与算法库

- **MUST** `VIS-09` 相机 SDK 只在适配层出现（`ARC-01`）。可能挂起或崩溃的原生库放进隔离单元（`ARC-04`）。
  - 理由 · 原生库挂起或崩溃时不能带倒整个软件，判定还要能按 `VIS-20` 处理。
- **SHOULD** `VIS-37` 视觉库和推理运行库的类型不超出算法模块。
- **SHOULD** `VIS-10` 相机接口优先用标准（GenICam 编程接口，GigE Vision、USB3 Vision 传输），业务逻辑不依赖某一品牌的相机。
- **MUST** `VIS-11` 回放或仿真状态在界面上醒目标出，这时不向 PLC 输出结果，也不写入正式的判定记录。
  - 理由 · 回放的结果如果进了产线，不良品会被当成合格放行。
- **SHOULD** `VIS-38` 提供离线回放模式：用图像序列代替相机，不连相机也能跑完整流程和测试（`TST-06`）。
- **MUST** `VIS-12` 商业视觉库和推理运行库按 `DEP-02` 写 ADR，按 `DEP-07` 不分发，除非许可证允许。运行授权缺失时启动就报错；运行中授权失效按 `VIS-20` 处理，到期前提前报警。
  - 理由 · 缺授权的软件会在生产中途停下；违反许可证还会带来法律风险。

## <a id="vis-pipeline"></a>帧管道与性能

- **MUST** `VIS-13` 帧不无限堆积：有队列时队列有界，满时按配置丢帧或拒绝，并计数报警。丢帧的产品按 `VIS-20` 判定。
  - 理由 · 无界队列会耗尽内存；静默丢帧的产品等于没有检测。
- **SHOULD** `VIS-39` 采集、处理和输出分开，用队列连接。
- **MUST** `VIS-14` 浸泡测试监控非托管内存和句柄（`IND-32`）。
  - 理由 · 图像缓冲区很大，一点泄漏也会在几天内拖垮软件，让产线停下。
- **SHOULD** `VIS-40` 图像和原生缓冲区有明确的所有者和释放点。
- **MUST** `VIS-15` 节拍是正确性的一部分：从触发到结果全程计时，按最坏情况设预算，超时按 `VIS-20` 处理。在真实相机和负载下验收，默认测试不依赖相机（`TST-06`）。
  - 理由 · 结果晚于节拍时，产品已经过了剔除位，判定就没有用了。
- **SHOULD** `VIS-16` 界面显示不阻塞处理，预览图可以降采样或跳帧。
- **MUST** `VIS-27` 图像和产品能对应：触发时绑定产品标识或序号，用独立于相机的计数（PLC、编码器或传感器）核对漏触发；统计相机丢包。计数不一致时按 `VIS-20` 处理，重新对齐后才恢复判定。
  - 理由 · 漏掉一次触发后，后面的图像都会对错产品，会放走不良品、剔除良品，而且结果看起来都正常。
- **SHOULD** `VIS-32` 优先用硬件触发；网络相机用专用网卡。

## <a id="vis-recipe"></a>标定、配方与环境

- **MUST** `VIS-17` 标定有版本、日期和有效期，记录相机序列号，可以备份和恢复（`IND-40`）。启动时相机序列号不符就不判定，按 `VIS-20` 处理；更换镜头或工位后要求重新标定；过期后怎么处理由工艺负责人定。
  - 理由 · 更换镜头或工位后标定就失效了，测量值会整体偏移，而且看不出来。
- **MUST** `VIS-18` 配方按产品管理，有版本，可以备份和恢复（`IND-40`），包括曝光、增益、ROI、触发延时、镜头和光源设置；相机的自动曝光和自动增益默认关闭，需要开启时写明原因，并在 `VIS-01` 的验收条件下验证过。修改配方经权限控制并写审计（`IND-26`、`IND-27`）。
  - 理由 · 配方决定判定结果，版本不清或被随意修改时，查不到判定为什么变了；相机自动调整曝光和增益时，成像条件会悄悄变化。
- **MUST** `VIS-35` 换型时核对当前配方和产品是否一致；加载配方和相机重连后，把参数写入相机并读回核对。不一致就不判定，按 `VIS-20` 处理。
  - 理由 · 用错配方，或者相机重连后回到默认参数时，整批产品的判定都可能是错的，而且不会报故障。
- **MUST** `VIS-19` 定期用标准件核对系统状态，让光源老化和镜头脏污能被发现。周期由工艺负责人定，结果写入记录，不通过时按 `VIS-20` 处理。
  - 理由 · 光源老化和镜头脏污是慢慢发生的，不核对就会一直漏检下去。
- **MUST** `VIS-29` 定位结果写明坐标系，发给机构或机器人前核对范围和匹配分数（`IND-15`），超限就不发送，按 `VIS-20` 处理；手眼标定定期核对。
  - 理由 · 机器人或机构按错误的坐标动作，可能撞坏设备或产品。
- **SHOULD** `VIS-42` 定位和测量结果写明不确定度。
- **MUST** `VIS-43` 部署文档写明工控机的运行环境：关闭系统自动更新和自动重启（补丁由人在计划窗口内安装）、节能和 USB 挂起，相机网卡设置，杀毒软件对图像目录和进程的排除；由现场人员按文档设置（`CFG-06`），上线前核对。
  - 理由 · 系统强制重启、网卡节能或杀毒软件扫描图像目录，都会让产线停下或丢帧。

## <a id="vis-faults"></a>判定与故障

- **MUST** `VIS-20` 超时、丢帧、相机断线、算法异常、配方或相机参数不一致、计数不一致、授权失效、记录或图像写入失败时的判定动作（判 NG、停线或复检）事先定义，由工艺负责人确认，不默认判 OK。结果没有按时到达 PLC 时，PLC 按同样的动作处理。
  - 理由 · 默认判 OK 时，任何故障都会把不良品放走；视觉软件崩溃时也发不出结果。
- **MUST** `VIS-21` 把结果写给 PLC 时有超时和握手：结果带产品序号，PLC 确认后才算送达（`IND-05`）；写入后读回按 `IND-16`；结果未知时不自动重发（`IND-17`）。
  - 理由 · 没有握手时，PLC 可能用上一个产品的结果；自动重发可能让结果作用到下一个产品。
- **MUST** `VIS-22` 视觉结果不执行安全功能（`IND-01`）。
  - 理由 · 视觉系统可能误判或失效，不满足安全功能的要求。
- **MUST** `VIS-23` 人工复判和重复检测另行记录（谁、何时、依据，`IND-27`），不静默修改或覆盖原结果。NG 改判放行经权限控制（`IND-26`）；NG 产品重新检测由工艺负责人定规则，不能反复检测到通过为止。
  - 理由 · 静默改掉原结果后，就查不到系统当时的判断；反复检测到通过，等于把不良品放走。
- **MUST** `VIS-36` 旁路或屏蔽检测的功能经权限控制并写审计（`IND-26`、`IND-27`），有时限，旁路期间在界面上醒目显示。旁路期间的产品标为未检测，不标为 OK。这里的旁路只指质量检测；安全联锁按 `IND-02` 不得旁路。
  - 理由 · 旁路忘了关时，后面的产品都没有检测，却都显示合格。
- **MUST** `VIS-34` 生产中统计 NG 率和（有得分时）得分分布，偏离基线时报警；使用模型时包括模型漂移。
  - 理由 · 镜头脏污或 ROI 偏移时，NG 率常常先掉到零，这时没有任何故障报警。

## <a id="vis-models"></a>模型（使用深度学习时）

- **SHOULD** `VIS-24` 模型带训练数据清单，能追溯到数据集和训练配置；供应商提供的模型记录来源和版本。
- **MUST** `VIS-25` 新模型先用和训练数据批次不重叠的保留图像集验证，或影子运行，再上线；能回滚到上一版本。
  - 理由 · 没有验证的模型上线可能大量漏检；不能回滚时只能停线。
- **MUST** `VIS-30` 固定推理运行库和 GPU 驱动的版本。
  - 理由 · 运行库或驱动一变，结果可能跟着变。
- **SHOULD** `VIS-41` 训练集和验证集按批次划分，防止数据泄漏。
- **MUST** `VIS-26` 模型文件按外部数据处理：不用不安全的反序列化加载（`CODE-07`），来源和许可证经核对（`DEP-02`）。
  - 理由 · 加载不安全的模型文件，等于执行外来的代码。

## <a id="vis-checklist"></a>发布清单

- [ ] 验收指标在真实产品和光照下测过，结果已记录；`VIS-03`、`VIS-28` 的评估已完成，样本量和置信度已记录。
- [ ] 回归图像集通过，漏检率和误检率不高于门禁。
- [ ] 回放或仿真时不向 PLC 输出结果，不写正式记录；相机断线和算法异常时的判定动作已实测。
- [ ] 视觉软件崩溃时，PLC 按事先定义的动作处理，已实测。
- [ ] 配方和产品不一致时不判定；相机重连后参数读回核对；旁路有时限，旁路期间的产品标为未检测。
- [ ] 漏触发和计数不一致已实测：按 `VIS-20` 处理，重新对齐后才恢复判定。
- [ ] PLC 握手已实测：超时和写入中断时不重发，结果不会落到下一个产品。
- [ ] 最坏负载下从触发到结果在预算内；超时和丢帧的判定动作已实测。
- [ ] 磁盘将满和写入失败已实测；标准件核对可用，结果写入记录。
- [ ] 标定和配方可以备份、恢复，版本写入判定结果。
- [ ] 工控机的运行环境按部署文档核对过。
- [ ] 使用模型时：保留图像集或影子运行通过，回滚已演练。
- [ ] 浸泡测试通过，内存、句柄和丢帧计数平稳。
