# <a id="pb"></a>上位机（工业监控与操作软件）

> **要点** 软件不做安全功能；通信隔离在适配器后；数据带质量和时间戳；报警与画面按 ISA-18.2、ISA-101。

适用于与 PLC、仪表、驱动通信，供操作员监视、操作、记录的软件。等级标记照常适用；7×24 运行的产线系统通常是 [L]。

状态：1.1。

**同时采用：** [通用规范](../general/README.md)和[桌面与本机软件](../desktop/README.md)。

和其他规范不一致时（建议，还没有项目验证）：操作画面以 `IND-22`–`IND-25` 为准，[桌面界面](../desktop/ui.md)的窗口结构、强调色和快捷键不适用时登记偏差；向 MES 或历史库传数据是现场约定的外传，按 `DAT-06` 写 ADR；工位机不按用户安装时登记为 `PKG-01` 的偏差。

## <a id="pb-safety"></a>B.1 安全功能边界

- **MUST** `IND-01` 软件不执行任何安全功能。人员与设备安全由按 IEC 61508、IEC 62061 或 ISO 13849 设计的安全 PLC 和硬接线联锁承担。
  - 理由 · 软件故障不能危及人员与设备。
- **MUST NOT** `IND-02` 软件能绕过、屏蔽或改写安全联锁：不写安全程序区和安全数据块，不强制（force）安全相关信号，不提供“旁路”按钮。
  - 理由 · 绕过联锁可能造成人身伤害和设备损坏。
- **MUST** `IND-03` 每条写入路径定义通信中断时的安全状态（保持、回到安全值、由 PLC 接管），由工艺负责人确认并写入文档；PLC 通过心跳检测上位机掉线，掉线后的动作由 PLC 程序决定。
  - 理由 · 掉线时输出状态不明会让设备处于危险状态。

## <a id="pb-comm"></a>B.2 设备通信

- **SHOULD** `IND-04` 每种协议（OPC UA、S7、Modbus TCP 等）一个适配器，藏在统一接口后面；业务逻辑不引用通信库。
- **MUST** `IND-05` 每次读写有超时；断线后按指数退避加随机抖动重连，有上限，不做紧密重连循环。
  - 理由 · 无超时或紧密重连会拖垮网络和设备。
- **SHOULD** `IND-06` 每台设备的连接状态（已连接、降级、断开）和最后一次成功通信时间持续显示给操作员。
- **SHOULD** `IND-08` [L] OPC UA 生产环境用 Sign 或 SignAndEncrypt，证书信任列表受管理；没有安全机制的协议（如 Modbus TCP）只在隔离的网段中使用。

## <a id="pb-data"></a>B.3 数据与采集

- **MUST** `IND-09` 每个值带质量（好、不确定、坏）和时间戳（源时间与服务器时间，UTC）；坏值或过期值按其状态显示，从不静默显示上一个好值。
  - 理由 · 把坏值当好值显示会误导操作员。
- **SHOULD** `IND-10` 工程单位、原始量程、换算和记录死区只在变量配置中定义一次，代码不重复换算。
- **SHOULD** `IND-12` 设备支持时用订阅（如 OPC UA 监视项）代替轮询；轮询按扫描等级（例如 100 ms、1 s、10 s）分组批量读取，并限制每台设备的请求速率。

## <a id="pb-write"></a>B.4 写入设备

- **MUST** `IND-14` 操作员写入设定值或命令前确认：显示目标设备、变量、旧值、新值和单位。
  - 理由 · 误操作的设定值会直接作用到设备上。
- **MUST** `IND-15` 发送前在边界检查量程、变化率和允许条件（由变量配置定义）；检查不通过就不发送。
  - 理由 · 越限或不满足条件的写入会损坏设备或产品。
- **SHOULD** `IND-16` 写入后读回；不一致时标出并记入审计。
- **MUST NOT** `IND-17` 自动重发结果未知的写入或命令；会使设备运动的命令每次都需要操作员的明确动作，不批量、不自动重复。
  - 理由 · 重复发送命令会让设备重复动作。

## <a id="pb-alarm"></a>B.5 报警管理（ISA-18.2 原则）

- **SHOULD** `IND-18` 报警有明确的状态：正常、未确认、已确认、恢复未确认、搁置、设计抑制、停用；状态变化记入历史。
- **SHOULD** `IND-19` [M+] 每条报警经合理化：优先级（3–4 级）、原因、后果、操作员动作、允许的响应时间；不满足的不是报警，改为事件或提示。
- **SHOULD** `IND-20` 确认按条进行，由登录用户完成并记录；搁置有时限和原因，并审计。
- **SHOULD** `IND-21` [M+] 提供报警洪流抑制与首出报警；统计每位操作员的报警率，与 ISA-18.2 / EEMUA 191 的目标比较（稳态约每 10 分钟 1 条以内）。

## <a id="pb-hmi"></a>B.6 操作画面（ISA-101 高性能 HMI）

- **SHOULD** `IND-22` 灰度基调：正常状态不用彩色；颜色只表示异常和报警，报警色保留给报警，不作他用。
- **SHOULD** `IND-23` 画面分层：总览 → 单元 → 设备细节 → 诊断；从总览到任一设备不超过 3 次操作。
- **SHOULD** `IND-24` 符号库统一：状态用形状加文字表达，同一符号全系统同义；数值总带单位，关键量配带正常范围的趋势。
- **SHOULD** `IND-25` 操作值刷新不慢于 1 秒；通信慢或中断不阻塞画面。界面的其他规则按第 21 节。

## <a id="pb-users"></a>B.7 用户、权限与记录

- **MUST** `IND-26` 角色（查看、操作、工程、管理）按最小权限；[L] 每人独立账号，不共用登录。
  - 理由 · 越权操作会改变设备状态。
- **MUST** `IND-27` 操作员动作的审计记录：谁、做了什么、何时（UTC）、在哪个站点、旧值、新值，需要时附原因；防篡改。
  - 理由 · 事故后无法追查谁改了什么。
- **MUST** `IND-28` [L] 受监管场合（如 21 CFR Part 11、EU GMP Annex 11）：电子签名注明含义并重新验证身份；审计记录不能关闭或编辑；保留期按法规。
  - 理由 · 受监管场合缺少电子记录会导致合规失败。

## <a id="pb-hist"></a>B.8 历史数据与时间

- **SHOULD** `IND-29` 按变量类别定义历史保留期，并据此估算存储。
- **SHOULD** `IND-30` 数据缺口明确记录，不跨通信中断插值；网络中断时本地缓存后补传。
- **SHOULD** `IND-31` 用 NTP 与厂区时钟源同步并监视漂移；存储一律 UTC。

## <a id="pb-247"></a>B.9 7×24 稳定性

- **MUST** `IND-32` [M+] 浸泡测试：[M] 至少 72 小时、[L] 至少 7 天，内存、句柄、线程数趋势平稳。
  - 理由 · 泄漏会在连续运行数周后导致宕机。
- **SHOULD** `IND-33` [M+] 服务受看门狗监督，崩溃后带退避自动重启；重启计数并报警。
- **SHOULD** `IND-34` 日志轮转并有磁盘空间保护；磁盘将满时报警，不停止采集。

## <a id="pb-62443"></a>B.10 网络安全（IEC 62443 基础）

- **SHOULD** `IND-35` [L] 按区域与管道划分：上位机在自己的区域，只开放必需的端口，连接关系写入文档。
- **MUST** `IND-36` [L] 所有用户和服务都经标识与认证；没有默认口令；服务账号最小权限。
  - 理由 · 默认口令和匿名访问是最常见的入侵途径。
- **SHOULD** `IND-37` [L] 默认安全：不用的服务关闭，加密协议默认开启；安全事件（登录、失败、配置变更）记录并可导出到厂区的日志系统。
- **SHOULD** `IND-38` [L] 有书面的补丁流程（操作系统、运行库、产品）和兼容性测试；随产品提供已安装系统的加固指南（系统设置、防火墙、移动存储策略）。

## <a id="pb-deploy"></a>B.11 离线现场部署与仿真

- **SHOULD** `IND-39` 安装、运行、更新都不依赖互联网：离线安装包和更新包附校验和。
- **SHOULD** `IND-40` 配置可导出备份（带版本）并可恢复；恢复流程经过测试。
- **SHOULD** `IND-41` 提供仿真模式：每种支持的协议有设备模拟器（OPC UA 模拟服务器、Modbus 从站模拟、PLC 仿真）；仿真状态在界面上醒目标出。
- **MUST** `IND-42` PLC 接口数据块带版本字：上位机连接时核对版本，不匹配就拒绝写入并提示；优先用符号访问；接口布局变化按对外契约管理（第 17 节）。
  - 理由 · 接口布局不一致会把值写到错误的地址。

## <a id="pb-checklist"></a>B.12 硬件在环测试清单 [M+]

- [ ] 真实 PLC 或仿真 PLC 加实际网络拓扑；记录固件版本与接口数据块版本。
- [ ] 拔网线、PLC 停机、重启上位机：状态显示、安全状态、重连、数据缺口记录都正确。
- [ ] 每个写入路径：确认、量程与允许条件拒绝、读回、审计记录。
- [ ] 报警：触发、确认、搁置、恢复、洪流抑制；报警率统计正确。
- [ ] 负载：最大变量数和最短扫描周期下的周期时间与 CPU、内存。
- [ ] 时间同步漂移、时区与夏令时切换下的历史数据和报警时间戳。
- [ ] 角色权限：每个角色只能做允许的操作；审计记录完整。
