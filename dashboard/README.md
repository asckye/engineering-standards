# 大屏

> **要点** 大屏要在远处一眼看懂，并且长期无人值守地运行。数据过期必须看得出来，出错能自己恢复。

状态：**草稿 0.2**。还没有用项目从零验证过。草稿阶段级别还可能调整，不按 [G-07](../general/00-purpose.md#purpose-gov) 升主版本。

**适用：** 在车间、调度室、展厅等场所长期显示数据的大屏和看板。

**不适用：** 操作员要在画面上操作设备的软件，按[上位机规范](../hmi/README.md)。

**同时采用：** [通用规范](../general/README.md)；用浏览器实现时加 [Web 规范](../web/README.md)，用桌面程序实现时加[桌面与本机软件](../desktop/README.md)。大屏只读且按固定分辨率设计，所以 `WEB-03`（对比度按 `DSH-05`）、`WEB-04` 的页面加载预算、`WEB-05` 的响应式要求和第 21 节的键盘规则不适用；`WEB-13` 的授权码 + PKCE 改按 `DSH-19`，令牌短期有效和服务端授权仍然适用。用桌面程序实现时，`DSH-15`、`DSH-22` 要求的运行状态和心跳外传是现场约定，按 `DAT-06`、`DIAG-01` 写 ADR；系统设置由部署步骤或人完成，产品本身不改（`CFG-06`）。

**等级：** 长期无人值守不等于 L 级。大屏只展示时通常是 M 级；操作决策依赖它或受监管时再按 L 级（这是 0.2 中 7×24 按 L 级的明确例外）。只作展示、没有人据此做决定的屏幕（如展厅），在项目 README 写明后，`DSH-11`、`DSH-23`、`DSH-24`、`DSH-25` 按 SHOULD。

## 级别怎么定

级别按[工程开发规范 0.7](../general/00-purpose.md#purpose-levels) 的标准定：按违反规则的后果，不看现有项目做到了多少。在本规范里，这些后果具体包括：

- 观众按过期、错误或读错的数据做决定；
- 屏幕卡死、黑屏或弹窗后没有人发现，或者要人到现场才能恢复；
- 大屏影响生产系统，或者打通了进入生产网的路径；
- 敏感数据、个人数据或凭据泄露；
- 通过大屏写入目标或设备。

## <a id="dsh-scope"></a>范围

- **MUST** `DSH-01` 大屏只读，不提供写入目标或设备的操作。需要操作时转到有权限和审批的系统。
  - 理由 · 展示设备通常放在公共场所，也没有审批；能写入就绕过了权限和确认。
- **SHOULD** `DSH-02` 写明观众和要回答的问题。
- **MUST** `DSH-24` 每个指标写明口径、单位、数据来源和更新周期。
  - 理由 · 口径不明时，同一个数字不同的人有不同的理解；没有更新周期也无法判断数据是否过期。

## <a id="dsh-layout"></a>显示与布局

- **MUST** `DSH-03` 写明目标分辨率、屏幕比例和拼接方式。分辨率不符时等比缩放，不出现滚动条和被裁切的内容。
  - 理由 · 大屏没有人去滚动，被裁掉的内容等于没有，数字被裁掉一位还会被读错。
- **MUST** `DSH-04` 关键数字和文字避开拼接缝。
  - 理由 · 拼接缝挡住一位数字和裁切一样，会被读错。
- **MUST** `DSH-05` 写明观看距离，最小字号按它确定，并在真实屏幕和实际距离上核对。对比度按 `UI-10`，状态不只靠颜色（`UI-13`）。
  - 理由 · 在实际距离上看不清就可能读错；只靠颜色时，色觉障碍的观众看不出状态。
- **SHOULD** `DSH-06` 一屏一个主题。轮播时每页停留足够长。
- **MUST** `DSH-25` 轮播时新告警在任何页面都看得到：常驻告警条、暂停轮播或跳到告警，告警持续时其他页面不被永久挤掉。大屏不是告警的唯一途径。
  - 理由 · 告警所在的页面没有轮到时，现场看不到告警；屏幕坏了时，告警也不能跟着消失。
- **SHOULD** `DSH-07` 颜色只表达状态和分类，告警色不作他用（`IND-22`）。

## <a id="dsh-data"></a>数据

- **MUST** `DSH-08` 每个区块或同一数据源的一组区块能看到数据时间。数据时间取来源数据的时间（`IND-09` 的源时间），不取缓存刷新或接口响应的时间。超过更新周期就明确标为过期，不静默显示旧值。比较时用服务器时钟，不用展示机时钟；断线时按最后一次对时加本机单调时钟继续判断。
  - 理由 · 旧值看起来和新值一样，观众会按过期的数据做决定；来源停了而缓存还在刷新时，画面看起来仍然是新的。
- **MUST** `DSH-09` 区分“没有数据”“数据为零”和“取数失败”。
  - 理由 · 取数失败显示成 0，观众会以为真的是 0。
- **MUST** `DSH-10` 前端不直连生产数据库或设备，经只读的聚合接口取数，大屏刷新不影响生产系统。展示端在生产网之外时，数据从生产网单向流出，经隔离区（区域划分按 `IND-35`）。
  - 理由 · 大屏刷新不能拖慢生产系统，也不能成为进入生产网的通道。
- **SHOULD** `DSH-26` 聚合层缓存并限流。
- **MUST** `DSH-11` 前端不计算指标，同一指标在本项目内只有一份实现（`P-09`）。大屏和报表用同一口径；报表不归本项目时按 `DSH-23` 对账。
  - 理由 · 同一指标算两次，大屏和报表的数字迟早对不上，观众不知道该信哪个。
- **MUST** `DSH-23` 核对指标的边界：班次和日切换、夏令时、不完整的周期；有来源报表时和它对账。
  - 理由 · 边界上的错误平时看不出来，却会让整班或整天的数字都不对。
- **MUST** `DSH-12` 时间按 UTC 存储，按现场时区显示（`I18N-03`）；同一种量的数字格式和单位全屏一致。
  - 理由 · 时区或单位不一致时，观众会读错数字和时间。
- **MUST** `DSH-28` 模拟数据源只在测试环境启用。屏上显示模拟、演示或人工录入的数据时醒目标出，不和实时数据混在一起。
  - 理由 · 模拟数据混进现场，观众会把它当成真实数据做决定。

## <a id="dsh-running"></a>长期运行

- **MUST** `DSH-13` 断线后按指数退避重连，恢复后自动刷新，不需要人到现场操作（`IND-05`）。重连间隔有上限，不因次数放弃；多块屏幕加随机抖动。
  - 理由 · 大屏没有人值守，不能自己恢复就会一直停在断线的画面。
- **MUST** `DSH-14` 浸泡测试至少 72 小时：内存、定时器、连接数和图表实例数平稳；切页时释放图表和订阅。
  - 理由 · 定时器和图表实例的泄漏要运行几天才暴露，那时已经没有人看着了。
- **MUST** `DSH-15` 展示机开机自启，现场不能用键盘、鼠标或触摸退出显示程序，崩溃后自动恢复；关闭系统和浏览器的自动更新、自动重启、休眠、通知和崩溃提示，补丁由人在计划窗口内安装；时钟同步。版本和运行状态不到现场也能查看。
  - 理由 · 无人值守的屏幕黑屏或弹窗时，要等有人路过才会发现。
- **MUST** `DSH-22` 能发现画面冻结和屏幕故障：屏上有走动的时钟，外部看门狗检查来自渲染循环的心跳（不是后台定时器），发现后自动重启显示程序并通知负责人。屏幕和拼接控制器的电源、信号源状态也纳入监控；读不到时写明谁每班巡检。
  - 理由 · 画面冻结时，旧数字看起来仍然正常，过期判断也停了。
- **MUST** `DSH-27` 用浏览器实现时，长期不刷新的前端能发现新版本并自动重载，后端兼容正在运行的旧前端（`MIG-01`）。
  - 理由 · 页面从不重载，后端升级后旧页面可能显示错的数据，而且要等有人到现场才会发现。
- **SHOULD** `DSH-16` 动效克制，不持续闪烁（`UI-31`）。屏幕类型容易残影时，固定内容定时位移或切换。

## <a id="dsh-performance"></a>性能

- **SHOULD** `DSH-17` 在实际展示机上设帧率和更新延迟预算。按数据更新周期批量更新，不按帧重绘全部图表。

## <a id="dsh-security"></a>安全与隐私

- **MUST** `DSH-18` 按摆放场所评估屏上内容，敏感数据和个人数据脱敏或不显示。
  - 理由 · 屏幕摆在谁都能看到的地方，上面的内容就等于公开了。
- **MUST** `DSH-19` 展示端用专门的只读设备凭据，可以单独撤销。凭据放在系统证书库或设备登录换取的 HttpOnly Cookie 中（`SEC-19`、`WEB-14`），不放在 URL、前端代码和构建产物里（`WEB-08`）。到期前自动续期并提前告警；被拒绝时按取数失败显示（`DSH-09`），不显示登录页。
  - 理由 · 展示机放在现场，凭据可能被看到或被拿走；凭据到期时屏幕没有人去登录，只会一直停在错误的画面。

## <a id="dsh-testing"></a>测试

- **SHOULD** `DSH-20` 在目标分辨率下做截图回归，覆盖极端数据：超长名称、很大的数、空数据和全部告警。
- **SHOULD** `DSH-21` 上线前在真实屏幕和实际观看距离下走查。

## <a id="dsh-checklist"></a>发布清单

- [ ] 目标分辨率和拼接方式下显示正确，含超长名称和很大的数：没有滚动条和裁切，关键数字不压拼接缝。
- [ ] 断网、后端重启和数据过期时显示正确，恢复后不需要人操作。
- [ ] 取数失败、没有数据和数据为零显示不同；画面冻结能被外部看门狗发现。
- [ ] 断电重启、程序崩溃和系统弹窗后自动恢复，不需要人到现场；版本和运行状态可以远程查看。
- [ ] 轮播时新告警看得到，告警持续时其他页面仍能显示。
- [ ] 凭据撤销和到期时屏上显示取数失败，不显示登录页。
- [ ] 指标和来源报表核对过班次和日切换。
- [ ] 浸泡测试通过，内存、定时器、连接数和图表实例数平稳。
- [ ] 真实屏幕和实际距离下走查通过。
- [ ] 屏上内容按摆放场所核对过，展示端只读。
