# <a id="accept"></a>27 验收与交付

> **要点** 软件交给别人运行之前，接收方要确认它达到事先说好的标准。交接后对方能自己安装、恢复和找到人，切换失败能退回去。

本节适用于有明确接收方的交付：交给客户、现场或其他团队运行。面向不特定用户的公开发布（下载、应用商店、开源）没有接收方，不适用，按发布清单（[26.1](26-checklists.md#checklist-release)）和[第 29 节](29-support-retirement.md#eol)；只有开发者自己用的工具也不适用。我们自己运行的服务替换在用系统时，仍按 `ACC-08`，由维护者确认。

上位机和视觉的现场验收另见[上位机规范 B.13](../../hmi-standard/references/rules.md#pb-acceptance)。

## <a id="accept-criteria"></a>27.1 验收标准与记录

- **MUST** `ACC-01` [M+] 验收标准由接收方确认并写明：谁验收，在什么环境，用什么数据或样品，什么算通过，不通过怎么办。最晚在开始验收前确认；有合同或定制开发时在正式开发前确认。改动同样由接收方确认。
  - 理由 · 事后才定标准，验收就变成争论，有问题的版本也可能被放行。
- **MUST** `ACC-02` [M+] 验收有记录（[模板](../assets/acceptance-record.md)）：版本和校验和、环境、日期、验收人、每项的结果和证据；没有测的写 `NOT RUN`。遗留问题写明严重程度、负责人和期限，由接收方确认后才算通过。S1 问题不能带着通过；写 `NOT RUN` 的项按遗留问题处理。
  - 理由 · 没有记录，上线后说不清验收过什么、带着什么问题上线。
- **SHOULD** `ACC-03` [M+] 验收环境和实际运行环境不一致的地方（模拟设备、样本数据、不同的网络）写进验收记录。

## <a id="accept-package"></a>27.2 交付内容

- **MUST** `ACC-04` [M+] 交付内容有清单，接收方不找开发者也能完成安装、配置、升级、回退和恢复：版本和校验和、运行环境要求、安装和升级步骤、配置项和默认值、备份与恢复步骤、许可证及到期日、第三方声明、已知限制、支持渠道和支持政策（`EOL-01`）。
  - 理由 · 交付内容不全时，现场出问题只能等开发者，停工时间不可控。
- **SHOULD** `ACC-05` [M+] 在干净的机器上按交付文档从零走一遍，把写漏的步骤补上。
- **MUST** `ACC-06` [M+] 交付配置中没有临时账号、默认口令和测试证书，调试开关和模拟数据源已关闭；产品自带的仿真或回放模式默认关闭并醒目标出（`IND-41`、`VIS-11`）。逐项核对，结果写进验收记录。
  - 理由 · 留在现场的调试入口就是没人管的后门，模拟数据还会被当成真实数据。
- **MUST** `ACC-07` [M+] 运行需要的账号、密钥、证书和许可证移交给接收方或按约定托管，写明负责人和到期日（`OPS-17`），不用开发者的个人账号运行。移交后，开发者手里的副本撤销或更换。移交过程不把凭据写进仓库或文档（`SEC-22`）。
  - 理由 · 开发者离开或账号失效时，系统会停下来，出了问题也查不到人。
- **SHOULD** `ACC-11` [M+] 维护交付台账：哪个客户运行哪个版本、联系人是谁，不入公开仓库（`SEC-22`）。没有台账时，供方说不清一个缺陷影响哪些现场，也通知不到人（`OPS-09`、`EOL-05`）。

## <a id="accept-cutover"></a>27.3 切换与回退

- **MUST** `ACC-08` [M+] 替换在用的系统前写切换方案，由接收方确认：时间窗口、步骤、负责人、通过标准、回退条件和回退步骤。切换前备份现有系统和数据。回退方案写明切换后新产生的数据怎么处理；有数据迁移时写明核对方法，切换时核对。回退步骤在测试环境或现场演练过。回退不可行时（如只前进的迁移）写明替代的恢复办法，由接收方确认。日常版本更新按 `MIG-05` 和发布流程，不单独写切换方案。
  - 理由 · 切换失败又退不回去，业务或产线就要停下来；回退时丢掉切换后的数据，损失可能比故障更大。
- **SHOULD** `ACC-09` [M+] 切换后有观察期：写明时长、谁值守、出问题找谁。观察期结束后才算交接完成。

## <a id="accept-handover"></a>27.4 培训与交接

- **SHOULD** `ACC-10` [M+] 操作和维护人员经过培训，内容至少包括日常操作、常见故障和什么时候找谁。培训材料随版本更新。

交接后谁负责运行按 `OPS-01` 写明，运行手册按 `OPS-02` 交给运行方。
