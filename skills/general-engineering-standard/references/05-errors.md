# <a id="errors"></a>5 错误处理与健壮性

> **要点** 错误按证据分类、消息可执行。写入后结果不明就停下交给人，绝不自动重放，这样才不会重复写入。

## <a id="errors-classes"></a>5.1 错误分类

每个对外报告的失败落在下表的一类中。分类决定能否重试、要不要锁定、给用户什么提示。

| 类别 | 含义 | 目标状态 | 调用方可否重试 |
|---|---|---|---|
| 输入无效 | 类型、范围、格式、未知字段 | 未改变 | 改正输入后可以 |
| 前提不满足 | 未连接、未绑定、对象被锁、需要离线 | 未改变 | 满足前提后可以 |
| 不存在、不唯一 | 对象找不到或有多个候选 | 未改变 | 按候选改正后可以 |
| 不支持 | 当前目标版本或设备不提供该能力 | 未改变 | 不可以 |
| 确认被拒绝或超时 | 人拒绝、超时、确认渠道不可用 | 未改变 | 只能由人重新发起 |
| 目标报告失败 | 厂商 API 或设备明确返回失败 | 已回滚或确认未变 | 按提示 |
| 部分完成 | 有确定的成功项和失败项 | 部分改变，已逐项说明 | 只处理失败项 |
| 结果未知 | 写入已发出，结果无法确认 | 未知 | 不可以（[5.3](#errors-unknown)） |
| 内部错误 | 本项目的缺陷 | 按发生阶段说明 | 不可以；附诊断编号 |

- **MUST** `ERR-01` 结果按证据分类，不按异常文本猜测。写入调用发出后的未分类失败一律归为“结果未知”，不报告为干净失败。
  - 理由 · 按异常文本猜结果会把未知的写入报成失败，引发重试。
- **SHOULD** `ERR-02` 错误消息说明发生了什么、已知原因和下一步怎么做；不含堆栈、本机路径、内部类型名和凭据。
- **SHOULD** `ERR-03` 先检查权限，再检查对象是否存在，避免错误信息泄露不该看到的对象。

## <a id="errors-swallow"></a>5.2 不吞异常

- **MUST** `ERR-04` 只捕获能处理的具体异常。`catch (Exception)` 只允许在边界：工具或命令入口、进程入口、界面命令、调度回调、清理与收尾。
  - 理由 · 宽泛捕获会掩盖缺陷。
- **SHOULD** `ERR-05` 每个吞掉异常的 `catch` 在 catch 行或块首标注 `/* swallow(<类别>): <原因> */`，类别取自闭集（cleanup、teardown、logging-failure、probe-optional、parse-fallback、ui、privacy 等），并由仓库检查计数，计数只减不增。
- **MUST** `ERR-06` 后台线程、调度到外部主线程的委托、插件生命周期方法内部捕获全部异常，把失败作为结果交回。未处理的异常会结束宿主进程（包括目标软件的进程）。
  - 理由 · 未处理的异常会结束宿主进程，包括目标软件。

## <a id="errors-unknown"></a>5.3 结果未知

- **MUST** `ERR-07` 写入、传输或通道在写入发出后中断时，先尝试取回结果（同一请求号查询，目标侧按请求号去重）；取不回时报告“结果未知”。
  - 理由 · 先取回结果，避免把已经成功的写入当作失败。
- **MUST** `ERR-08` 结果未知后锁定受影响的范围（会话、项目或设备），锁定持久化；只有人检查目标的实际状态后经确认渠道解除，没有自动化接口能解锁。
  - 理由 · 锁定防止在状态不明时继续写入。
- **MUST NOT** `ERR-10` 宿主、客户端、批处理或重试策略自动重放结果未知的写入。重新预览也不等于获准再次写入。
  - 理由 · 重放会造成重复写入或设备重复动作。

## <a id="errors-cleanup"></a>5.4 资源清理

- **SHOULD** `ERR-12` 临时文件和目录每次运行新建（随机后缀）。
- **MUST** `ERR-22` 清理临时文件和目录时，只删除本次运行创建的内容，或者本产品专用临时目录中已过期的内容（`DAT-05`）；删除前核对路径仍在预期根目录下，而且不是符号链接或重解析点。日志轮转和按保留期删除（`DAT-05`、`DAT-10`、`IND-34`）不算这里的清理，删除前同样核对路径。
  - 理由 · 清理跟着链接或错误的变量走，就会删掉用户的数据。
- **MUST** `ERR-13` 断开或退出时不隐式改变外部系统的状态（保存、关闭、复位、停机）；需要时作为显式操作提供。
  - 理由 · 隐式的保存或复位是没有人批准的写入，可能改写数据或让设备停机。

## <a id="errors-timeouts"></a>5.5 超时与等待

- **MUST** `ERR-14` 每个跨边界调用有超时：按操作类别设预算（例如普通调用、首次连接、编译或导入这类长操作），预算集中定义、可经配置覆盖，并写在用户文档中。
  - 理由 · 没有超时的调用会让会话永久挂起。
- **MUST** `ERR-16` 派发前的取消返回“已取消”；写入派发后不能中止时，等待真实结果（超时按 `ERR-14`、`ERR-07` 报告结果未知），不报告成已取消。
  - 理由 · 把已经派发的写入报成已取消，用户会以为目标没变。

## <a id="errors-lifecycle"></a>5.6 进程生命周期

- **MUST** `ERR-18` 启动时校验配置和必需文件，有错就以明确的退出码和消息退出（fail fast），不在半配置状态下运行。
  - 理由 · 半配置运行会产生错误结果。
- **SHOULD** `ERR-20` [M+] 需要独占某个目标实例时用租约文件（所有者 PID、启动时间、状态），租约状态为忙碌或不确定时拒绝竞争者；不靠删除租约文件绕过。
- **MUST** `ERR-21` 状态文件原子写入（写临时文件后替换）；审计写不进去时拒绝写入目标，读取照常。
  - 理由 · 半写的状态文件会让程序无法启动；没有审计的写入无法追查。
- **MUST NOT** `WIN-14` 按进程名、窗口标题或模式匹配结束进程。只结束自己启动的进程：记录 PID 和启动时间，结束前核对可执行文件路径。
  - 理由 · 按名称结束进程会关掉用户的其他程序。
