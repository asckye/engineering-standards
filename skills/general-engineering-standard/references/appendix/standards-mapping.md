# <a id="mapping"></a>附录：标准对照

这两张表用来查漏，也方便项目向客户说明。它们不是合规结论，也不是法律意见：有没有满足，要看项目实际做了什么。

**状态：** 覆盖指有 MUST 规则，或者规则足以覆盖这一实践；部分指只覆盖一部分，或者只是 SHOULD、只对部分项目类型或等级；未覆盖指本规范没有写。

## <a id="mapping-cra"></a>欧盟 Cyber Resilience Act

依据 [Regulation (EU) 2024/2847](https://eur-lex.europa.eu/eli/reg/2024/2847/oj/eng) 和委员会的[指南 C(2026) 5252](https://ec.europa.eu/newsroom/dae/redirection/document/131456)。

判断步骤（依据第 2、3 条和指南，不是法律意见）：

1. 下载或安装后在用户一侧运行的软件是带数字元素的产品；只经浏览器访问的 Web 应用和网站通常不是，除非它是某个产品必需的远程数据处理。医疗器械、车辆、航空、船用设备和国防专用产品不在范围（第 2 条）。
2. 收费、付费才有版本或更新、靠它变现其他服务、把收集个人数据作为使用条件，都算商业活动；免费开源、只接受自愿捐赠或另售咨询，通常不算。
3. 商业活动下是制造商；法人长期维护、面向商业集成但不变现的开源软件，是开源软件管理者（第 24 条）；个人维护的不变现开源软件没有 CRA 义务。
4. 默认类可以自我评估；附件 III、IV 的产品按第 32 条（技术描述见实施条例 2025/2392）。

制造商的主要义务：

- 支持期按预计使用时间定，不短于五年（预计不足五年时等于预计使用时间），写到年月并在购买时告知；后续版本免费且不增加额外成本时可以只修最新版（第 13(8)、(10)、(19) 条）。
- 每个安全更新保留十年或到支持期结束，取较长者（第 13(9) 条）。
- 编制机器可读的 SBOM，至少覆盖顶层依赖，不必公开（附件 I 第二部分）。
- 技术文档、符合性评估、符合性声明和 CE 标志（第 13(12) 条；小微企业有简化文档，第 33(5) 条）。

下表的编号指附件 I，第一部分写作 2(a)，第二部分写作 II(1)。
