## 逐项检查

- [ ] 正确性：主要路径和边界情况对吗？并发、取消、超时下呢？
- [ ] 设计与简单：该不该做？放在这里对吗？有没有更简单的做法？是否用了已有的扩展点和共享组件？
- [ ] 可读性与命名：不看说明能读懂吗？名称说的是“是什么”吗？
- [ ] 测试：代码出错时测试会失败吗？测试快、稳、独立吗？
- [ ] 错误处理：只在边界校验？错误明确、不吞异常？写入后的失败按“结果未知”处理？
- [ ] 安全：输入、路径、子进程、密钥、去敏、确认是否符合第 6 节？并发和锁符合第 3 节吗？发给外部模型的内容允许吗（`AI-18`）？[M+] 新增的个人数据进了清单吗（`DAT-08`）？
- [ ] 性能：热路径上有没有多余的调用、分配或 IO？有计时证据吗？
- [ ] 一致：与项目已有的名称、结构、错误码一致吗？
- [ ] 文档与注释：注释说明原因吗？公开 API 有文档注释吗？有没有过期注释？

## AI 生成的代码另外核对

**MUST** REV-07：AI 生成的代码用同样的标准评审，另外核对：

- [ ] 新增的包确实是要用的那个（包名和发布者）。
- [ ] 没有推测性抽象和防御性膨胀（1.4）
- [ ] 没有没人要的配置项和测不到的状态测试
- [ ] 调用的 API 确实存在于对应版本的文档中
- [ ] 没有任务范围外的改动
- [ ] 没有放宽任何检查

## 界面改动另外核对

[21.13 界面评审清单](../references/21-ui.md#ui-checklist)：

- [ ] 只用 token；没有字面颜色和字号；新 token 已加入设计系统。
- [ ] 桌面和上位机的页面类型（列表 + 详情、表格、分组列表）符合[桌面界面](../../desktop-app-standard/references/ui.md#ui-layout)；每类功能一个入口。
- [ ] 七种状态齐全；加载、空、错误三种状态分开。
- [ ] 每个决策区最多一个默认按钮；写入审批等权重、回车不批准；破坏性走确认面板。
- [ ] 键盘可完成全部操作；焦点可见；桌面和上位机的访问键无冲突；自动化名称完整。
- [ ] 对比度矩阵通过；桌面和上位机的高对比下有描边、无阴影、状态靠形状和文字。
- [ ] 桌面和上位机在中英文、1024 × 640、200% 缩放下不截断。
- [ ] 文案用动词、说清后果；错误说明怎么办。

## 阻止合并的情况

**MUST** REV-05：以下任一项阻止合并。

- MUST 违规且无 ADR
- 新增分析器警告
- 检查被删除或放宽且未获批准
- 生成文件与生成器输出不一致
- 修复缺少回归测试
- 契约变化没有说明
- 含密钥或客户数据
- 未解决的“必须修改”意见
