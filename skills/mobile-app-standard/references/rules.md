# <a id="pf"></a>移动 App

> **要点** 遵循平台规范；权限按需申请；密钥进系统安全存储；分阶段发布。

状态：2.1。

**同时采用：** [通用规范](../../general-engineering-standard/references/contents.md)。

- **SHOULD** `MOB-01` 遵循平台规范：iOS 按 Apple Human Interface Guidelines，Android 按 Material Design；跨平台框架同样遵守各平台的导航、返回和手势约定。
- **SHOULD** `MOB-02` 架构采用 MVVM 或单向数据流；界面状态由单一来源驱动，可在没有界面的情况下测试。
- **SHOULD** `MOB-03` [M+] 需要离线使用时以本地数据为先，后台同步；同步冲突有明确规则（例如以服务端版本号判断并提示用户），不静默覆盖。
- **SHOULD** `MOB-04` 网络请求有超时、带退避的重试（只对幂等请求）和离线提示；弱网下界面不卡住。
- **SHOULD** `MOB-05` 节省电量和流量：批量后台任务交给系统调度器，大文件只在 Wi-Fi 或经用户同意时下载，不做高频轮询。
- **SHOULD** `MOB-06` 权限在用到时、结合上下文申请，只申请最少的权限；被拒绝时功能降级并说明。
- **MUST** `MOB-07` 隐私：数据最少化；应用商店的隐私标签与实际行为一致；第三方 SDK 的数据收集纳入清单。
  - 理由 · 隐私标签与行为不符会被下架。
- **MUST** `MOB-08` 令牌与密钥存放在 Keychain（iOS）或 Keystore（Android）；不放在普通偏好设置或文件中。
  - 理由 · 普通存储中的令牌容易被提取。
- **SHOULD** `MOB-09` 证书固定只在威胁模型证明需要时使用，并有轮换方案，避免证书更换导致应用失联。
- **MUST** `MOB-10` 深度链接用 Universal Links / App Links 校验域名；链接参数按外部输入校验，不能直接触发写入。
  - 理由 · 外部链接可能触发非预期的写入。
- **MUST** `MOB-11` 通知内容不含敏感数据。
  - 理由 · 锁屏上的通知谁都能看到。
- **SHOULD** `MOB-17` 推送通知需用户授权；点击后导航到明确的页面。
- **MUST** `MOB-12` 支持 VoiceOver 与 TalkBack 的标签和顺序，支持系统字号（如 Dynamic Type）。
  - 理由 · 做不到时，读屏和放大字号的用户就用不了；面向公众的产品在不少地区有法律要求。
- **SHOULD** `MOB-18` 触控目标不小于 44 pt / 48 dp。
- **SHOULD** `MOB-14` [M+] 发布前对照应用商店审核规则自查；经内部测试渠道（TestFlight、内部测试轨道）验证后再分阶段发布，监视崩溃率，异常时暂停。
- **MUST** `MOB-15` 崩溃报告需用户同意，并在隐私说明中列出收集的数据（[DIAG-01](../../desktop-app-standard/references/diagnostics.md)）。
  - 理由 · 未经同意上报崩溃数据违反隐私规则。
- **SHOULD** `MOB-16` 写明最低系统版本政策（例如支持最近若干个主版本）和设备测试矩阵（小屏、大屏、平板、低端机、最新系统）。

## <a id="pf-checklist"></a>F.1 移动发布清单

- [ ] 设备矩阵上的冒烟测试通过；离线、弱网、权限被拒绝时的行为正确。
- [ ] VoiceOver/TalkBack 与最大字号下走一遍主要流程。
- [ ] 隐私标签、权限说明文字与实际一致；崩溃报告需同意。
- [ ] 内部测试渠道验证通过；分阶段发布的比例和暂停条件已设定。
