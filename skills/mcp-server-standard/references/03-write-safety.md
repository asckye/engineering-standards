# 写入安全层

> **要点** 模型可能出错，也可能被项目里的文字诱导。写入要先规划、由人在独立窗口批准；结果不明就停下，绝不重放。

威胁前提：服务防的是模型出错、提示注入和客户端自己回答审批。以当前用户身份运行的恶意程序不在防护范围内，这一点写进项目的威胁模型（没有威胁模型时写入 README）。

本层的**写工具**指改变目标、设备、共享库或用户已有文件的工具。只写服务自己的数据目录、或把结果写到新建输出目录的工具叫**本地工具**。预览、审批、执行状态、结果未知、审计和备份的规则，只有写明时才适用于本地工具；分级、不可信内容和路径规则适用于所有工具。

## <a id="ws-class"></a>分级

- **MUST** `WS-01` 每个工具显式登记安全级别（至少区分只读、本地、写入、破坏性；能执行代码、改系统或写在线设备时单列），不按名称推断。
  - 理由 · 级别是安全开关，推断错了写入就绕过了审批。
- **SHOULD** `WS-02` 每个工具显式设置 `readOnlyHint`、`destructiveHint`、`idempotentHint`、`openWorldHint`，按最有副作用的动作和参数组合取值。带预览参数的工具 `readOnlyHint` 为 false；只操作本机目标时 `openWorldHint` 为 false。注解只是提示，安全不依赖它。
- **MUST** `WS-03` 能执行外部命令、脚本或宏时，只执行随产品发布的白名单条目，参数逐个校验。没有工具、配置或数据文件能增改白名单。
  - 理由 · 否则模型或注入内容可以执行任意操作。

## <a id="ws-preview"></a>预览

- **MUST** `WS-04` 写工具都能预览。预览不写目标、文件或设备，不等待审批，返回变更清单和计划哈希。
  - 理由 · 人和模型都要先看到会发生什么；预览路径写入会绕过审批。
- **MUST** `WS-05` 审批可能被关闭、或调用路径上没有审批窗口时，写工具默认预览。有审批窗口且执行前已经规划时，可以不默认预览，以免每次写入多一轮调用。
  - 理由 · 没有人确认的路径上，默认预览是写入前仅剩的一道检查。
- **MUST** `WS-06` 请求审批前先用同一参数在只读范围内规划，审批窗口的变更清单和计划哈希都来自这次规划。规划被拒绝就直接返回；没有变化时可以不请求审批。
  - 理由 · 人批准的必须是实际要做的修改；没有规划，审批窗口和复核都没有依据。

## <a id="ws-approval"></a>审批

- **MUST** `WS-07` 写工具的执行由人在审批窗口中批准（`WS-15` 的关闭开关和 `WS-16` 的一次性项目除外）。调用方的参数、元数据、批处理和客户端表单（包括 MCP elicitation）都不能代替。
  - 理由 · 客户端自己显示、自己回答的表单证明不了有人确认。
- **MUST** `WS-08` 审批请求号由服务生成。决定绑定请求号、计划哈希和去敏后的参数摘要，只能使用一次；迟到、重复、不匹配或格式错误的决定一律按拒绝处理。
  - 理由 · 防止伪造、重放或把批准用到别的请求上。
- **MUST** `WS-09` 审批窗口显示工具、目标、变更清单和剩余时间。“批准”不是默认按钮，不自动获得焦点，也没有快捷键；请求出现后约 500 毫秒内不响应；没有“全部批准”。普通写入的“批准”“拒绝”等权重；破坏性操作可以把“拒绝”设为默认。
  - 理由 · 防止一次习惯性回车或误点就批准写入。
- **MUST** `WS-10` 来自项目的文本在审批窗口中作为纯文本显示，剥除控制字符、双向文字控制符（U+202A–202E、U+2066–2069）和 Unicode 标签字符（U+E0000–E007F），不能用换行伪造多行，长度有上限。
  - 理由 · 项目文本可能冒充界面说明，误导工程师。
- **SHOULD** `WS-36` 审批窗口标明哪些文本来自项目；客户端自报的名称标“未验证”。
- **SHOULD** `WS-38` 一个请求只在一个窗口中询问。送达后连接断开时返回 `APPROVAL_UNAVAILABLE`，不转到另一个窗口。
- **MUST** `WS-11` 拒绝、超时、无可用窗口都不执行。
  - 理由 · 没有人确认的写入就是未授权的写入。
- **SHOULD** `WS-12` 这几种结果用不同的错误码：`APPROVAL_DENIED`、`APPROVAL_EXPIRED`、`APPROVAL_UNAVAILABLE`。它们的 `retryable` 都是 false，但模型的下一步不同：拒绝后不再发起，过期后告诉工程师并由人决定是否重新发起，无窗口时提示工程师打开审批窗口。
- **MUST** `WS-13` 批准后、执行前，在串行通道内复核目标身份、参数摘要、计划哈希和受影响对象的状态指纹，不一致返回 `PLAN_STALE`。一个计划只执行一次。
  - 理由 · 批准之后目标或参数可能已经变化。
- **MUST** `WS-37` 调用方给的输入文件进入计划哈希（大小和内容哈希），批准之后到执行之前再次核对。
  - 理由 · 路径没变、内容变了时，人批准的就不是实际写入的内容。
- **MAY** `WS-40` 多步计划整体审批一次，批准绑定计划哈希。
- **MUST** `WS-44` 整体审批的多步计划，每一步限定在批准的范围内，发散就停下并重新规划。
  - 理由 · 否则后面的步骤可能写入没有人批准的内容。
- **MUST** `WS-14` 审批开关、可写范围、一次性项目范围等安全配置只能由人修改，没有工具能改，也不能写这些文件（包括经短文件名、链接或文件 ID 的写法）。设置缺失或损坏时按安全的一侧处理。
  - 理由 · 防止自动化关掉自己的保护。
- **MUST** `WS-15` 如果提供关闭审批的开关，它只影响安全级别为“写入”的操作；破坏性、执行代码、改系统、写在线设备的操作，以及 `WS-29`、`WS-39` 的写入仍要审批。关闭时每个执行结果带警告，并把开关变化写入审计。
  - 理由 · 关闭后写入不再经人确认，模型要知道这一点，事后也要能查到何时关闭；破坏性操作和写设备不能因为一个开关就没有人看。
- **MAY** `WS-16` 一次性项目上的普通写入可以免审批。是否一次性由服务端判定：按规范化后的完整路径判断（解析 `..`、链接、短文件名、大小写），调用方声明不算。只有安全级别为“写入”、且只改这个一次性项目的操作可以免审批；破坏性、执行代码、改系统、写在线设备、共享数据（`WS-39`）和根目录外的路径（`WS-29`）仍要审批。
- **MUST** `WS-39` 写入影响多个项目的共享数据（例如系统库）时单独处理：每次审批，审批窗口写明影响范围，先备份；没有回滚手段或是团队共用的库时可以拒绝。
  - 理由 · 一次写错会影响所有用到它的项目。

## <a id="ws-execution"></a>执行状态

- **MUST** `WS-17` 写工具的结果和错误都带 `execution`，放在结构化内容中，不只写在文字里，取值是下表的闭集。读工具和本地工具不要求带。
  - 理由 · 模型读这一个字段就知道目标有没有被改，不用从文字推断。

| 值 | 含义 |
|---|---|
| `not_started` | 没有开始修改：执行前被拒绝、预览或没有变化 |
| `rolled_back` | 开始修改后失败，目标与调用前相同（已回滚或确认未变） |
| `committed` | 修改已提交 |
| `partial` | 所有项的结果都已确定，其中有成功项，也有失败或未执行项（用于批处理、多步计划和不能回滚的目标） |
| `unknown` | 有任何一项无法确定是否被修改（批处理和多步计划也一样，同时列出已确定的项） |

- **MUST** `WS-18` `execution` 为 `unknown` 当且仅当错误码是 `OUTCOME_UNKNOWN`。
  - 理由 · 两个字段不一致时，消费方不知道该信哪个。
- **MUST** `WS-19` 写工具的 `retryable: true` 只能和 `not_started` 或 `rolled_back` 一起出现。重发需要重新审批时为 false。
  - 理由 · 可能已写入时提示重试，就会把修改做两次。
- **MUST** `WS-20` 结果按证据分类，不按异常文本猜测。写入调用发出后的未分类失败一律归为结果未知。
  - 理由 · 按异常文本猜结果，会把未知的写入报成失败，引发重试。
- **SHOULD** `WS-42` 写后校验的结果写明覆盖范围，说明“通过”不等于其他内容没变。

## <a id="ws-unknown"></a>结果未知

- **MUST** `WS-21` 写入发出后中断时，先尝试取回结果：适配层按服务生成的写入编号记录状态并去重，服务重连后查询，查不到才报告结果未知。查询过的未知编号登记为“未开始”，迟到的同号写入不再执行。
  - 理由 · 先取回结果，才不会把已经成功的写入报成未知，也不会不必要地打断工程师。
- **MUST NOT** `WS-22` 服务、客户端、批处理或重试策略自动重放结果未知的写入。重新预览也不等于获准再次写入。
  - 理由 · 重放会造成重复写入。
- **MUST** `WS-23` 结果未知后暂停受影响范围（项目或实例）的写入，提示工程师检查目标的实际状态；工程师经审批窗口或目标软件内的确认后才恢复。
  - 理由 · 状态不明时继续写入会扩大损坏。
- **MUST** `WS-24` 暂停状态能跨服务进程重启，并且没有工具能单独解除。
  - 理由 · 规范建议客户端在 stdio 服务退出后重启它，暂停只在内存里就会被一次重启清掉。
- **MUST** `WS-41` 服务重启时从审计中找出只有“开始”、没有结果的写入，先查询，查不到就暂停。
  - 理由 · 进程崩溃时可能来不及记录暂停，只有审计知道哪些写入发出过。
- **MUST** `WS-25` 派发前取消时不执行。写入派发后不能中止时，等待或取回真实结果并写入审计，不假装已取消。
  - 理由 · 把已经派发的写入报成已取消，模型和工程师都会以为目标没变。

## <a id="ws-audit"></a>审计与备份

- **MUST** `WS-26` 写入发出前落盘一条“开始”记录，结果确定后补记。审计只追加，用哈希链防篡改，有校验命令。审批决定也写入审计。“开始”记录写不进去时拒绝写入。
  - 理由 · 没有审计的写入无法追查，崩溃后也不知道哪些写入发出过。
- **MUST** `WS-43` 写入完成后“结束”记录写不进去时，结果照常返回并带警告，不把已提交的写入报告成失败。
  - 理由 · 把已提交的写入报成失败，模型会重试，同一修改就做了两次。
- **MUST** `WS-27` 破坏性操作执行前自动备份到新建的目录并核对副本，备份失败就不执行；备份路径写入结果和审计，不自动删除。
  - 理由 · 破坏性操作之后无法恢复工程师的数据。

## <a id="ws-input"></a>不可信内容与路径

- **MUST** `WS-28` 来自项目或设备的自由文本只作为数据返回，放在数据字段中，不拼进描述、摘要或错误消息。剥除控制字符（保留换行和制表符）、双向文字控制符和 Unicode 标签字符，超长时截断并注明。
  - 理由 · 防止项目数据中的文字被模型当成指令执行。
- **MUST** `WS-29` 工具给出的文件路径二选一：只接受固定根目录之下的相对路径，并拒绝 `..`；或者根目录之外的写入经审批，审批窗口显示规范化后的完整路径，不截断。两种方式都拒绝 UNC、控制字符和保留设备名，根目录之下的每一级都不能是链接或联接点；确需网络共享时由人按 `WS-14` 把它加入根目录。审批之前不访问根目录外的路径（包括存在性检查和哈希）。工具读取调用方给的文件时，只读人配置的根目录之下的文件。
  - 理由 · 防止写到预期目录之外；访问 UNC 共享还可能发送用户的凭据哈希。
- **MUST** `WS-30` 导出和输出不覆盖已有文件，除非调用显式允许并经审批。
  - 理由 · 静默覆盖会丢失工程师的文件。
- **MUST** `WS-31` 外部提供的压缩包和数据包只按数据处理：条目名校验、名称忽略大小写后唯一、拒绝链接条目，文件数、大小和压缩比有上限，不执行包内任何代码。产品自身的更新包不在此列，按发布规则校验完整性。
  - 理由 · 防止压缩炸弹和路径穿越。
- **MUST** `WS-32` 凭据不进入审批摘要、哈希、审计、日志和工具结果，去敏规则统一一处实现。项目内容默认不写日志。
  - 理由 · 凭据和客户数据会经日志和摘要泄露。
- **MUST** `WS-33` 工具调用触发的子进程不经 shell，用绝对路径和参数列表，限制超时和输出大小。启动本产品自己的界面时不限超时和输出大小；确需系统提权的步骤可以经 shell 启动。这些情况都不把调用方输入拼进命令。
  - 理由 · 防止命令注入。
- **MUST** `WS-34` 服务与适配层、审批窗口之间的本机管道只允许当前用户访问，拒绝远程客户端，限制帧大小；名称不可预测或核对对端身份，防止管道名被抢占。审批通道严格解析，未知字段和重复字段拒绝；适配层的内部协议可以按版本容忍未知字段。
  - 理由 · 防止同机其他用户冒充对端回答审批。
- **SHOULD** `WS-35` 维护威胁模型文档：资产、信任边界、STRIDE 威胁、措施及其测试、已知缺口。新增信任边界时更新。
