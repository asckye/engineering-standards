# <a id="testing"></a>12 测试

> **要点** 测试证明主要行为和规定的失败路径；快、稳、不依赖真实资源。

## <a id="testing-layers"></a>12.1 分层

| 层 | 允许使用 | 证明 | 何时运行 |
|---|---|---|---|
| 单元 | 进程内内存计算 | 逻辑、映射、决策表 | 每次构建 |
| 集成 | 本机临时目录、管道、子进程、127.0.0.1 上的夹具、模拟器 | 进程边界、协议、故障恢复 | 合并门 |
| 契约 | 对外契约的快照 | 契约没有意外变化 | 合并门 |
| 离线夹具 | SDK 元数据、XSD、真实格式样本 | 与目标格式一致 | 合并门 |
| 实机 [M+] | 真实目标或硬件，只用一次性项目 | 原生行为 | 发布前；结果记入台账 |

## <a id="testing-prove"></a>12.2 每个改动要证明什么

| 改动 | 必须有 |
|---|---|
| 新功能 | 主要路径测试 + 下面列出的相关失败路径 |
| 缺陷修复 | 修改前失败、修改后通过的测试 |
| 替换代码路径或重构 | 新旧行为对等的测试 |
| 对外契约变化 | 重新生成的快照，差异逐项说明 |
| 新命令或脚本 | 至少真实运行一次 |
| 对目标调用的顺序、参数或线程改变 | 前后调用序列对照；实机验证计划 |

必须覆盖的失败路径（与改动相关的部分）：确认被拒绝、超时或不可用；结果未知后锁定且不重放；边界输入（路径越界、超限、格式错误）；凭据去敏；隔离单元超时、崩溃、坏回复；回滚。

## <a id="testing-rules"></a>12.3 规则

- **MUST** `TST-01` 每个功能有主要行为的测试和 12.2 列出的相关失败路径测试；不写证明不了主要功能的防御性测试。
  - 理由 · 没有主要行为测试，回归会直接到用户手里。
- **MUST** `TST-05` 测试不等真实时间超过 1 秒：注入时钟或计时接缝；计时参数在 CPU 满载时仍成立。
  - 理由 · 真实等待让测试变慢并在负载下偶发失败。
- **MUST** `TST-06` 默认测试不连接网络、真实目标或设备；可以在 127.0.0.1 上启动自己的夹具和模拟器。
  - 理由 · 依赖网络和设备的测试不稳定。
- **SHOULD** `TST-07` 夹具使用真实格式的脱敏数据。
- **MUST** `TST-08` 快照和 golden 文件只由正式工具重新生成，差异逐项说明；从不自动接受。
  - 理由 · 自动接受快照会把回归写进基线。
- **SHOULD** `TST-09` [M+] 每个测试套件登记最少通过数和最多跳过数，防止“过滤写错、一个没跑也算通过”；下限只升不降。
- **SHOULD** `TST-10` 测试互相独立，不依赖执行顺序和共享状态。
- **SHOULD** `TST-11` [M+] 实机验证记入台账：目标版本、日期、项、结果；没跑写 `NOT RUN`。
