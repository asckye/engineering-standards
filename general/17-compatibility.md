# <a id="compat"></a>17 兼容、升级与迁移

> **要点** 同一主版本内只做增量；格式带版本并自动迁移。

- **MUST** `MIG-01` 同一主版本内对外契约只做增量（新功能、新可选参数、新字段、新错误码）；消费方容忍未知字段和未知错误码。
  - 理由 · 破坏性变化会让现有客户端失效。
- **MUST** `MIG-02` 破坏性变化（改名、删除、改必填、改含义、改安全属性）升主版本，并在发布说明中附生成的新旧对照表。
  - 理由 · 没有对照表，用户无法迁移。
- **SHOULD** `MIG-03` 弃用：在目录和说明中标注替代项与计划移除的版本，调用时给出弃用警告；至少保留一个次版本再移除（公开 API [M+] 保留一个主版本）。
- **MUST** `MIG-04` 配置和数据格式带版本号；启动时把旧版本迁移到当前版本，迁移前备份原文件；遇到更新的格式拒绝并提示升级，不静默丢弃未知设置。
  - 理由 · 升级后配置丢失或程序无法启动。
- **SHOULD** `MIG-06` [M+] 维护目标版本支持矩阵：已验证、已构建未验证、不支持；写入发布说明。
- **SHOULD** `MIG-07` 实验性或隐藏开关登记在一张表中：用途、默认值（关）、负责人、移除期限；到期删除。
