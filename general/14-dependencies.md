# <a id="deps"></a>14 依赖与许可

> **要点** 每个依赖都是长期成本：许可证合规、版本精确锁定、可离线还原，不分发厂商运行库。

- **SHOULD** `DEP-01` 新增依赖写明用途、许可证、维护状况和更轻的替代；[M+] 运行时依赖由维护者批准。
- **MUST** `DEP-02` 允许的许可证：MIT、Apache-2.0、BSD-2/3-Clause、ISC；MPL-2.0 等弱著佐权需评审；GPL/AGPL 和带使用限制或收费条款的许可证（例如某些断言库、快照库的新版本）不进入发布物，除非有 ADR。
  - 理由 · 许可证冲突会让产品无法合法发布。
- **MUST** `DEP-03` 版本精确锁定：中央版本管理 + 锁文件，CI 以锁定模式还原；传递依赖同样锁定。
  - 理由 · 未锁定的版本让构建不可重现，问题难以复现。
- **SHOULD** `DEP-04` [M+] 构建可以离线还原：本地包源或缓存配置入库，构建过程不临时下载。
- **SHOULD** `DEP-05` 原样引入的第三方源码放在 `third_party/<name>/`，记录上游地址、标签或提交、许可证文件；本地修改逐项列出。
- **MUST** `DEP-06` 发布物带 `THIRD-PARTY-NOTICES`，列出每个随包组件的许可证文本；保留原始版权声明。派生自他人项目时保留原许可声明，再加自己的。
  - 理由 · 缺少声明违反许可证义务。
- **MUST** `DEP-07` 厂商 SDK 和运行库不提交、不分发，除非许可证明确允许；构建引用本机安装（不复制到输出），运行时从本机安装加载。
  - 理由 · 分发厂商运行库违反许可并造成版本冲突。
- **SHOULD** `DEP-08` 提到第三方产品时写全称，需要处注明商标归属，并声明本项目与厂商无隶属关系；不使用厂商标志。

## <a id="deps-integrity"></a>14.1 交付物完整性

- **MUST** `DEP-10` 每个发布文件附 SHA-256；更新器和安装说明都核对它。
  - 理由 · 用户无法核对下载是否完整或被替换。
- **SHOULD** `DEP-11` [M+] 发布附 SBOM（CycloneDX）和构建来源证明（例如托管 CI 的 artifact attestation）。
