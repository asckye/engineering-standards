# <a id="ui"></a>21 界面设计

> **要点** 人始终掌控，风险越高摩擦越大。只用 token；每对前景与背景满足 WCAG 2.2 AA；写入审批等权重、回车不批准。

本章对所有带界面的项目有效。桌面工具的参考 token 集在[桌面界面](../desktop/ui.md)（Apple HIG 风格，Windows 优先）；Web 与移动另按 `web/`、`mobile/` 的平台规范；工业操作画面另加 `hmi/` 的规则；大屏另按 `dashboard/`；移动 App 的键盘和触控按 `MOB-12`。下面的尺寸和交互是默认值；项目的取舍（行高、确认方式、页面数等）记在自己的 ADR 中。

## <a id="ui-principles"></a>21.1 原则

1. **人始终掌控**：自动化和 AI 只能请求，执行由人决定；超时按拒绝处理。
2. **清晰优先**：一屏回答一个问题；颜色只表达状态和风险，不做装饰。
3. **克制**：界面退后，数据（对象名、路径、变更）走到前面；用留白和分组建层级，少用线和阴影。
4. **风险越高，摩擦越大**：只读不打扰；写入一次点击但回车不批准；破坏性先确认，默认是取消。
5. **永远说清状态**：连接、暂停、超时、结果在发生的位置即时可见，不靠弹窗。

## <a id="ui-tokens"></a>21.2 Token

- **SHOULD** `UI-01` 颜色、字号、间距、尺寸、圆角、阴影、时长只引用 token；视图和样式中不写十六进制颜色和字面字号。新值先加入设计系统，再使用。

## <a id="ui-color"></a>21.5 颜色与对比

- **MUST** `UI-10` 每一对实际使用的前景与背景在每个主题中满足 WCAG 2.2 AA：文字 ≥ 4.5:1，图形、控件边界、焦点环、状态指示 ≥ 3:1；只有禁用态豁免。由对比度矩阵测试核对。
  - 理由 · 对比不足会让文字、边界和焦点看不清。
- **SHOULD** `UI-11` 区分“强调底上的文字”（`label-on-accent`，放在 `accent` 实底上）和“强调色文字”（`accent-text`，放在普通底色上）；不把 `accent` 直接当文字色。
- **MUST** `UI-13` 不只靠颜色传达信息：状态配图标和文字；一屏的强调色实底不超过一处。
  - 理由 · 只靠颜色会让色弱用户误读状态。

## <a id="ui-icons"></a>21.6 图标

- **SHOULD** `UI-15` 图标含义在全产品固定；状态标记形状互不相同（i、!、✓、✕、—），高对比下仍可区分。

## <a id="ui-components"></a>21.7 组件与状态

每个可交互组件都定义七种状态：默认、悬停、按下、焦点（焦点环，任何模板不得去掉）、禁用（`label-tertiary`）、选中（窗口激活时 `accent` 实底加白字，非激活时浅填充加勾选）、错误（边框与内联文字）。

| 组件 | 规则 |
|---|---|
| 按钮 | 主要（`accent` 底，每个决策区最多一个）、次要（`fill-control` 底）、破坏性（`destructive-text`）；高 32，决策按钮 44；文字用动词说清后果，不用“确定”。 |
| 输入框 | 高 32，`border-control` 边框；错误时边框变色并在下方显示文字，焦点移到第一个出错字段。 |
| 表格与列表 | 行高按产品选定的 token（36 或 44）；列表单选，选中立即更新详情；表格多选用复选框；↑↓ 移动，到底不循环；被截断的内容能用键盘取得全文。 |
| 页签与分段控件 | 整组一个 Tab 停靠点，方向键切换，Home/End 到首尾。 |
| 徽标与标记 | `radius-full`；读屏名称包含完整含义（“2 项待批”），不只是数字。 |
| 提示条（Banner） | 持续的全局状态；严重级别图标加文字，可带一个直达处理的按钮；不自动消失，不闪烁。 |
| 提示（Toast） | 短暂反馈，排队逐条显示；不遮挡焦点元素和决策按钮；可用键盘关闭。 |
| 对话框与确认面板 | 模态：Tab 在内循环，Esc 等于取消，关闭后焦点回到触发元素。确认面板：问句标题、一句后果、取消为默认按钮；影响大的操作要求输入确认词。 |
| 进度与倒计时 | 已知总量用确定进度，否则不确定进度加文字说明当前操作；倒计时环线宽 3，少于 30 秒变为警告色，旁边显示剩余秒数文字。 |
| 空、加载、错误 | 空：48 px 图标 + `title-2` 一句话 + 一句下一步，最多一个操作。加载：列表顶部进度。错误：就地内联提示或提示条，说明发生了什么、原因、怎么办。三者不混用。 |

## <a id="ui-patterns"></a>21.8 交互模式

### 风险分级与确认

| 等级 | 标记 | 确认方式 |
|---|---|---|
| 只读 | 灰色“只读” | 不确认 |
| 写入 | 蓝色“写入” | “拒绝”“批准”等权重：同样底色、尺寸、等宽单元格，拒绝在左；两者都不是默认或取消按钮；回车和 Esc 都不触发，只能空格或点击 |
| 破坏性 | 红色“破坏性” | 默认按钮是“拒绝”（响应回车）；“批准并…”用 `destructive-text`，点开确认面板，面板默认是“取消”，确认按钮永不响应回车 |

- **MUST** `UI-16` 风险等级由可信的一侧（服务端或本机审批逻辑）计算，不取自调用方声明的提示。
  - 理由 · 调用方可能把写入声明为只读。
- **MUST** `UI-17` 每个请求单独决定，没有“全部批准”。请求自动打开时焦点放在标题上，绝不放在决策按钮上；请求出现或页面切换后 500 ms 内决策按钮不响应输入。
  - 理由 · 防止一次习惯性回车或误点就批准写入。
- **SHOULD** `UI-18` 倒计时用环加文字，读屏只在 30 秒和 10 秒时播报；超时即拒绝。
- **MUST** `UI-19` AI 或自动化请求的审批决定立即生效并记入审计，不提供撤销；界面只给一条结果反馈（“已拒绝…”“已批准，正在执行”）。
  - 理由 · 撤回已返回给调用方的决定会造成状态不一致。
- **SHOULD** `UI-20` 请求卡显示：发起方（自报名称标“未验证”）、目标、操作清单、风险等级文字、剩余时间；原始参数放在默认收起的区域，敏感值已替换；来自项目的数据标明“只作数据显示”。
- **SHOULD** `UI-21` 可撤回的普通操作不预先确认，事后提供撤销；不可撤回的操作先确认。

## <a id="ui-a11y"></a>21.9 键盘与无障碍

- **MUST** `UI-24` 全部功能可用键盘完成；Tab 顺序等于视觉顺序；没有键盘陷阱（模态内循环除外）；Esc 只关闭临时界面，从不触发破坏性操作。
  - 理由 · 键盘用户无法操作；Esc 误触发破坏性操作。
- **SHOULD** `UI-26` 每个可交互元素有自动化名称（UIA 名称、`aria-label` 等）；页面打开时焦点放在页面标题；重要状态变化用 live region 播报（一般 polite，新的待决定请求可用 assertive）。
- **SHOULD** `UI-27` 指针目标不小于 24 × 24 px；用读屏（讲述人、NVDA）、高对比和 200% 缩放各走一遍主要流程 [M+]。

## <a id="ui-copy"></a>21.10 本地化、文案与动效

- **SHOULD** `UI-29` 文案：短句、主动语态、动词开头；标题说清要发生什么（“在项目 Demo 中放置 2 个设备”）；错误说发生了什么、原因、怎么办，不责备用户，不用感叹号；技术标识原样用等宽。
- **SHOULD** `UI-31` 动效克制，只表达状态变化；系统开启“减少动态效果”时滑入改为淡入；不闪烁，状态快速多次变化时合并显示。

## <a id="ui-ai"></a>21.11 AI 或自动化驱动界面（适用时）

- **MUST** `UI-32` AI 只能打开白名单中的页面，从不包括审批页和设置页；审批或设置为当前页、有模态界面、最近 1.5 秒内有人的输入、或页面正在执行命令时拒绝 AI 的显示和预填。
  - 理由 · 防止 AI 把人引到审批或设置上。
- **SHOULD** `UI-34` 预填的字段旁有可见标记“AI 预填，待确认”和可用键盘的“清除预填”，状态也暴露给读屏；AI 操作界面后显示“AI 操作了界面 · 工具 · 客户端 · n 秒前”。

## <a id="ui-test"></a>21.12 界面测试

- **SHOULD** `UI-37` 设计值断言（尺寸、字号、token 值）随批准的设计变更更新；行为、键盘、无障碍、审批类断言不放宽（G-06）。
- **SHOULD** `UI-38` [M+] 有可用工具时自动查无障碍问题：Web 用 axe，Windows 桌面用 Axe.Windows 或 Accessibility Insights（要在桌面会话里运行程序），移动用平台的检查工具。新增问题不合并（`ENF-02`），合并门跑不了的放到发布前。工具查不到的按 `UI-27` 人工走查。

## <a id="ui-checklist"></a>21.13 界面评审清单

- [ ] 只用 token；没有字面颜色和字号；新 token 已加入设计系统。
- [ ] 桌面和上位机的页面类型（列表 + 详情、表格、分组列表）符合[桌面界面](../desktop/ui.md#ui-layout)；每类功能一个入口。
- [ ] 七种状态齐全；加载、空、错误三种状态分开。
- [ ] 每个决策区最多一个默认按钮；写入审批等权重、回车不批准；破坏性走确认面板。
- [ ] 键盘可完成全部操作；焦点可见；桌面和上位机的访问键无冲突；自动化名称完整。
- [ ] 对比度矩阵通过；桌面和上位机的高对比下有描边、无阴影、状态靠形状和文字。
- [ ] 桌面和上位机在中英文、1024 × 640、200% 缩放下不截断。
- [ ] 文案用动词、说清后果；错误说明怎么办。
