# <a id="build"></a>15 构建、验证与发布

> **要点** 一个入口命令；检查分层运行，合并门只跑受影响的部分；发布只核对证据和打包。

## <a id="build-tiers"></a>15.1 验证分层

| 档 | 何时 | 内容 | 可作发布证据 |
|---|---|---|---|
| 开发自检 | 开发中 | 受影响的快速检查 | 否 |
| 合并门 | 每次合并前，在开发主机 | 受影响的检查，约 15–20 分钟（[★ 快速交付](00d-fast-delivery.md#fast)） | 否 |
| 完整检查 [M+] | 每晚无人值守；没有夜间任务的项目在发布前对要发布的提交运行 | 冷启动、无缓存的完整检查，预算 45 分钟 | 是；失败或超时阻止下一次发布 |
| 发布前检查 [M+] | 发布准备阶段 | 实机、升级、性能基线、模糊测试、浸泡（[12.1](12-testing.md#testing-layers)） | 是 |
| 发布 | 维护者确认后 | 只核对证据、打包、上传 | 不适用 |

- **MUST** `BLD-01` 一个构建入口：同一条命令在本机和 CI 中构建、测试、打包。
  - 理由 · 本机与 CI 走不同路径时，结果对不上。
- **SHOULD** `BLD-02` 检查只在各档之间移动或按身份复用，不删除。复用只针对同一机器上输入完全相同的干净通过；计时敏感的检查总是重跑。
- **SHOULD** `BLD-03` [M+] 托管 CI 每次推送运行；本机合并门是权威时，CI 不阻塞合并，失败在主干上向前修复（写 ADR 说明选择）。
- **SHOULD** `BLD-04` 可重现：固定 SDK 版本（如 `global.json`）、锁文件、确定性构建；生成器逐字节输出并提供 `-Check`；生成物不含时间戳和本机信息；发布物的构建按 `BLD-07`。

## <a id="build-release"></a>15.2 版本与发布

- **SHOULD** `BLD-06` SemVer；预发布写作 `X.Y.Z-beta.N` 或 `X.Y.Z-rc.N`，在托管平台标为预发布且不设为最新版。
- **MUST** `BLD-07` 每次发布前维护者确认；发布期间不改代码；已公开的发布、标签和资产不改写，问题用新补丁版本修正。发布物从要发布的提交的干净检出构建，标签指向这个提交。
  - 理由 · 发布期间改代码会让产物与验证证据不符。
- **SHOULD** `BLD-09` [M+] 发布说明结构固定：摘要、变化、升级、已知限制、验收状态；附从台账生成的“未在真实目标上验证”清单（编号连续，供测试者引用）。
- **SHOULD** `BLD-10` [M+] 每次合并后做一次发布演练（不上传），让发布本身只剩上传。
- **MUST** `PKG-07` 包内容由一份清单决定，由检查核对；不含开发源码、密钥、厂商 SDK、测试数据和调试入口。
  - 理由 · 防止把密钥、开发文件或厂商 SDK 发出去。
- **SHOULD** `PKG-08` [M+] 预发布交给测试者时附：测试清单（按“未验证”清单编号）、反馈模板（Issue 模板，填写清单编号、版本、环境）；反馈先记入反馈台账，复核后再写入真机台账。
- **SHOULD** `BLD-11` [M+] 能控制范围时分阶段发布：服务和商店先给一小部分，自动更新分批，现场软件先上一个工位或一条线；配置、规则和模型的推送同样；风险大的功能也可以用开关（`MIG-07`）。写明看什么（没有遥测时看问题反馈和诊断包，`DIAG-01`）、看多久、谁看、什么情况下暂停。暂停时停止分发或取消“最新”，不改写已发布的内容（`BLD-07`）。
- **MUST** `BLD-12` [M+] 本版升级后不能直接退回上一版本时（只前进的迁移、旧版本读不了新格式 `MIG-04`），发布前写明恢复办法，由维护者确认，有接收方时由接收方确认，并写进发布说明。
  - 理由 · 用户升级后才发现退不回去，数据只能靠备份恢复，或者带病运行。
- **SHOULD** `BLD-13` [M+] 发布构建用发布配置，开发依赖不随包发布（`PKG-07`）。原生代码开启编译器和平台的缓解措施（如 ASLR、DEP、CFG，Linux 上 PIE、RELRO），用工具核对（如 BinSkim）；托管和脚本语言保持运行时的安全默认值。符号文件不随包，按版本保留，用于分析崩溃。
