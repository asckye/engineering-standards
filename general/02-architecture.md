# <a id="arch"></a>2 架构

> **要点** 外部系统只在适配层出现，绝大部分代码因此能离线测试；不稳定的厂商组件放进隔离进程，故障不带倒主进程。

## <a id="arch-layers"></a>2.1 分层与依赖方向

分层：入口、应用层、领域逻辑、适配层，只向下依赖；契约层被各层引用。

```text
入口
  传输、界面、命令行：只做绑定与呈现
  ↓
应用层
  边界校验、确认、审计、排队、错误映射
  ↓
领域逻辑
  规则、计划、换算；以纯函数为主，不引用外部库
  ↓ 经接口
适配层
  厂商 API、设备协议、文件、进程、时钟、网络

契约（横向）
  DTO、错误码、协议消息；不引用任何层
```

- **MUST** `ARC-01` 依赖只向下；外部系统只在适配层出现，适配器由组合根注入。
  - 理由 · 外部系统散落各处，代码就无法离线测试和替换。
- **SHOULD** `ARC-02` [M+] 依赖方向由工程引用和架构测试强制，不靠约定。
- **MUST** `ARC-03` 外部对象（厂商对象、设备连接、界面对象）不跨层或进程边界；跨边界只传 DTO 和标识。
  - 理由 · 外部对象跨边界会引发线程和生命周期故障。

## <a id="arch-isolation"></a>2.2 隔离不稳定的外部组件

- **MUST** `ARC-04` 可能挂起、崩溃或有线程亲和性的组件（厂商 API、驱动、原生库）放在隔离单元：独立进程，或专用线程加有超时的调度器；它故障不能带倒主进程。
  - 理由 · 厂商组件崩溃会带倒整个服务。
- **SHOULD** `ARC-05` 进程间协议有版本号和握手（协议版本、对方身份、一次性 nonce），不匹配就拒绝。
- **SHOULD** `ARC-06` 对同一目标实例的调用串行化；不访问目标的操作不排在它后面。
- **MUST** `ARC-07` 隔离单元超时、退出或回复损坏时，这一代标为故障，显式恢复前拒绝后续调用，不自动重放。
  - 理由 · 故障后的状态不可信，继续调用会扩大损坏。

## <a id="arch-errors"></a>2.3 错误模型

- **SHOULD** `ARC-08` 组件内部用语言惯用的方式报错（异常或错误值）；边界（API 入口、界面命令、命令行）把它们映射为对外错误，映射表只此一处。
- **SHOULD** `ARC-09` 错误码是闭集，集中定义在契约中，UPPER_SNAKE 拼写。

## <a id="arch-logging"></a>2.4 日志与诊断

- **SHOULD** `ARC-11` 结构化日志（消息模板），每条带请求号；日志级别有约定（Information 记开始、结束、耗时；Debug 记参数摘要）。
- **MUST** `ARC-12` 以 stdio 提供协议的进程，stdout 只输出协议；日志写 stderr 或文件。
  - 理由 · stdout 混入日志会破坏协议通信。
- **SHOULD** `ARC-14` [M+] 对目标的写入在发出前落盘一条“开始”记录，结果确定后补记；重启后先处理只有“开始”的记录。
- **SHOULD** `ARC-15` [M+] 审计（谁、何时、做了什么、结果）与运行日志分开；审计只追加、按哈希链防篡改，不自动删除。
- **MUST** `ARC-17` 日志、审计、诊断包写出前去敏：凭据替换为占位符，用户名与用户目录换成占位符，用户项目内容只在 Trace 级别记录（默认关闭）。
  - 理由 · 日志和诊断包会泄露凭据和客户数据。

## <a id="arch-extend"></a>2.5 扩展点

- **SHOULD** `ARC-18` 每个扩展点是一张登记表（名称、分类、适用版本、权限等级）加一处实现；注册、发现、文档和测试都读这张表。

## <a id="arch-modules"></a>2.6 模块、目录与版本标识

```text
src/<Product>.Contracts  .Core  .Host  .Adapters.<X>  .Ui
tests/<Product>.<Component>.Tests
build-tools/   reference/   schemas/   manifest/（生成）
docs/{architecture,adr,standards,plan,process,status,design,templates,guides,reference,postmortems}
third_party/（原样保留，含许可证）
```

| 对象 | 标识与规则 |
|---|---|
| 产品 | SemVer `X.Y.Z[-beta.N\|-rc.N]`，单一来源文件派生全部版本号 |
| 对外契约 | 整数契约版本；只增量变化，破坏性变化升版本并附迁移表 |
| 持久化格式 | `<name>/<N>`，各自编号，读取端能迁移旧版本 |
| 进程间协议 | 整数版本，握手交换，必要时兼容 N−1 |
| 目标版本 | 闭集的版本键，未登记的版本不当作别名 |
