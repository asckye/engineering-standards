# <a id="ops"></a>28 运行与运维

> **要点** 出问题时要有人先知道，知道该找谁、怎么恢复。先止损，再查原因。备份要真的能恢复，会到期的东西不能等到期才发现。

本节适用于交付后还在运行的软件。哪些规则适用、由谁负责，取决于谁来运行：

| 运行方式 | 运行方 | 适用 |
|---|---|---|
| 我们自己运行的服务 | 我们 | 全部 |
| 在客户或现场机器上长期运行或无人值守的软件（上位机、视觉、大屏、现场服务） | 客户或现场 | 供方提供能力和资料：`OPS-01`、`OPS-02`；`OPS-03`、`OPS-05`（产品能报告状态、发出告警）；`OPS-12`、`OPS-13`、`OPS-15`（备份恢复手段和步骤，供方测过）；`OPS-17`（清单和到期提示）；`OPS-09`（通知客户）。监视、执行备份和演练由运行方负责，合同另写的除外（`OPS-01`）。`OPS-21`、`OPS-23`–`OPS-25` 约束供方接触现场时的操作。其余不适用 |
| 用户自己操作的软件和公开发布的软件（桌面工具、移动 App、开源下载） | 用户 | 只有 `OPS-09`（经发布说明和安全公告通知），以及 `OPS-17`、`OPS-18`（我们自己持有的证书、域名和签名密钥）。其余不适用，不需要登记例外 |

监控数据默认留在本机。发到本机之外（客户网络或供方）要运行方明确同意，写明内容和接收方，并写 ADR（`DAT-06`、`DIAG-01`）。

Web 的具体做法见 `WEB-25`、`WEB-30`–`WEB-32`。项目类型的规则更具体时以它为准，但不放宽本节的 MUST（[0.1](00-purpose.md#purpose-parts)）。

## <a id="ops-owner"></a>28.1 责任与手册

- **MUST** `OPS-01` [M+] 写明谁负责运行：谁监视，出问题找谁，谁能决定停机、回退和通知用户，非工作时间怎么办。软件在客户现场运行时，写明客户和供方各负责什么。负责人是人，不是代理。只有一个人能处理时，写明这个人不在时谁能拿到恢复所需的凭据和手册。
  - 理由 · 出事时找不到人或没人敢决定，停机时间就会拖长。
- **MUST** `OPS-02` [M+] 运行手册（[模板](../templates/runbook.md)）入库，随版本更新：启动和停止、健康检查、常见故障和处置、备份和恢复、升级和回退、日志位置、联系人在哪里找。机器地址、客户名称、联系人和许可证信息不入库（`SEC-22`、`GIT-07`），放在运行方保管的现场资料中，手册只写去哪里找；现场资料不算 `SEC-22` 所说的文档。
  - 理由 · 处理故障的人不一定是开发者，没有手册就只能猜。

## <a id="ops-monitor"></a>28.2 监控与告警

- **MUST** `OPS-03` [M+] 长期运行或无人值守的软件，不用登录到运行机器也能看出是否健康：健康检查或心跳报告进程和关键依赖（目标、数据库、磁盘）的状态。未认证的检查只回总体状态和版本（`SEC-16`），依赖明细要认证或只在本机显示。
  - 理由 · 否则要等用户发现才知道坏了，而且说不清坏了多久。
- **SHOULD** `OPS-04` [M+] 服务监控流量、错误率、延迟和资源用量，告警阈值入库。
- **MUST** `OPS-05` [M+] 长期运行或无人值守的软件，影响用户的故障和磁盘将满有告警，发给 `OPS-01` 写明的负责人；告警通道随 `OPS-13` 的演练一起测试。
  - 理由 · 告警发不出去或没人收，就等于没有监控。
- **SHOULD** `OPS-06` [L] 告警按用户能感受到的症状设置，每条链接处置步骤。没有人需要处理的不是告警，定期清理。

## <a id="ops-incident"></a>28.3 事故响应

事故是已经影响用户或现场的问题，级别按 [13.1](13-defects.md#bugs-triage)，步骤见[处理事故手册](00c-playbooks.md#play-incident)。

- **MUST** `OPS-07` [M+] 事故先止损，再查原因。可能影响人员或设备安全时，先按现场规程让设备进入安全状态（`IND-03`），何时恢复运行由工艺负责人决定。其余情况用停用功能、重启、回退或切换到备用把影响止住。停用和回退不算修复，恢复后按 `BUG-04` 定位根因；恢复前能保留的日志和诊断包先保留。回退和切换也是写入，由自动化或 AI 发起时仍按 `P-04`、`SEC-03`；写入结果未知时仍按 `ERR-08`、`ERR-10` 处理，不为恢复而重放。
  - 理由 · 边查边试会延长停机，还可能扩大损坏；在设备上，安全永远排在恢复前面。
- **SHOULD** `OPS-08` [M+] S1 事故指定一人负责，记录带时区的时间线和已做的操作。
- **MUST** `OPS-09` [M+] 影响用户的数据、安全或结果正确性时，主动通知受影响的用户：发生了什么、影响范围、用户要做什么、下次更新的时间。在现场运行时通知客户；没有联系方式的公开用户经发布说明、安全公告和下载页通知。法规要求上报的，事先写明渠道和时限，按时上报。
  - 理由 · 用户不知道时，会继续用错误的结果做决定；逾期上报还有法律后果。
- **SHOULD** `OPS-10` [M+] 复盘的教训变成检查项、测试或告警，不只写在文档里（`BUG-06`）。
- **SHOULD** `OPS-11` [L] 每年至少演练一次事故响应：告警能到人，手册能用，通知渠道畅通。

## <a id="ops-backup"></a>28.4 备份与恢复

- **MUST** `OPS-12` [M+] 我们运行的系统里的数据和配置有自动备份：写明备份什么、多久一次、保留多久、放在哪里。备份不和原数据放在同一台机器或同一块磁盘上，备份失败有告警（`OPS-05`）。在现场运行的软件提供备份和恢复手段并测过（`IND-40`），由运行方执行（`OPS-01`）；备份存到机器之外按 `DAT-06`。
  - 理由 · 备份和原数据一起损坏，或者备份早就失败了却没人知道，就什么都没有了。
- **MUST** `OPS-13` [M+] 在备用机或隔离环境中演练恢复，不动在线系统：从备份恢复到可用状态，并记录所需时间。频率写进运行手册；[M] 至少每年一次，备份方式或架构改变后再做一次；[L] 至少每季度一次。
  - 理由 · 没有恢复成功过的备份，不能算有备份。
- **MUST** `OPS-14` [L] 写明恢复时间目标（RTO）和恢复点目标（RPO，最多丢失多长时间的数据），由维护者或客户确认。备份频率和架构按它设计，演练结果和它对照。
  - 理由 · 否则要到事故时才发现恢复要几天，或者丢了一整天的数据。
- **SHOULD** `OPS-15` [M+] 机器损坏时能恢复：有重装步骤或系统镜像，配置和授权怎么恢复写明，并在干净的机器上试过。
- **SHOULD** `OPS-16` [M+] 备份用单独的权限：生产账号和代理不能删除或覆盖已有备份。

## <a id="ops-expiry"></a>28.5 会到期的东西

- **MUST** `OPS-17` [M+] 证书、密钥、令牌、许可证和域名有清单：用途、到期日、负责人、更新步骤。到期前至少 30 天告警；更新要走采购或要到现场时再提前。在现场运行时，软件自己提前提示，清单交给运行方。
  - 理由 · 到期是常见的意外停机原因，而且往往发生在没人看着的时候。
- **MUST** `OPS-18` [M+] 怀疑泄露或持有人离开时，轮换或撤销相关密钥。
  - 理由 · 不轮换的话，泄露的密钥和离开的人一直能访问系统。
- **SHOULD** `OPS-19` [M+] 密钥轮换不需要改代码或长时间停机，步骤写进手册。

## <a id="ops-capacity"></a>28.6 容量

- **SHOULD** `OPS-20` [M+] 写明磁盘、内存、连接数和许可证数的上限和增长估算，按它规划扩容或清理。

## <a id="ops-change"></a>28.7 生产变更与访问

- **MUST** `OPS-21` [M+] 生产环境的变更有记录：谁、何时、改了什么、什么版本、结果。紧急手工改动事后补记。操作员的日常操作按 `IND-27`，不算这里的变更。
  - 理由 · 事故时第一个问题就是最近改了什么。
- **SHOULD** `OPS-22` [M+] 配置和基础设施的改动来自入库的版本（`WEB-28`），手工改动同步回仓库；现场配置留在现场备份中（`IND-40`）。
- **MUST** `OPS-23` [M+] 运维和开发人员对生产环境的访问按最小权限，用个人账号，访问有记录；操作员账号按 `IND-26`。排查默认只读，需要写入时走变更记录。生产数据复制到开发环境前先脱敏（`DAT-07`）；不能脱敏的按项目类型的规则（如 `VIS-08`）。
  - 理由 · 共用账号和常开的写权限，出事后查不到人，也容易误操作。
- **MUST** `OPS-24` [M+] AI 代理不持有生产环境和现场设备的写权限：恢复、回退、变更、撤销凭据和删除数据由人执行，或经 `SEC-03` 的独立界面逐次确认；代理可以准备命令和记录（`AI-10`、`CFG-06`）。
  - 理由 · 代理可能误判，也可能被项目里的文字诱导，一条错误的命令就能损坏生产环境。
- **MUST** `OPS-25` [M+] 供方远程接入现场由运行方逐次开启，有时限，用个人账号，有记录，用完关闭；不留常开的远程工具和共用口令。
  - 理由 · 常开的远程通道没人看着，既是入侵途径，也可能在无人知情时写入设备。
