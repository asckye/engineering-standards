# <a id="code"></a>3 代码规范

> **要点** 语言无关的写法规则；具体工具见语言附录。格式交给工具，评审不争论格式。

本节对任何语言有效；各语言的具体做法见语言附录 [L1](languages/l1-csharp.md#lcs)、[L2](languages/l2-typescript.md#lts)、[L3](languages/l3-python.md#lpy)。

- **SHOULD** `CODE-01` 遵循语言的官方命名与风格约定；格式由格式化工具统一，不在评审中争论格式。
- **SHOULD** `CODE-02` 一个文件一个公开类型或模块，文件名等于类型名；目录与命名空间或包一致。
- **MUST** `CODE-04` 新代码启用最严格的类型检查（C# 可空引用类型、TypeScript `strict`、mypy/pyright strict）。
  - 理由 · 空引用和类型错误是最常见的运行时缺陷。
- **MUST** `CODE-05` 异步：界面线程和请求线程上不同步阻塞等待；取消信号一路传下去；不发出无人处理错误的“即发即弃”任务。
  - 理由 · 阻塞等待会造成死锁和界面冻结。
- **MUST** `CODE-06` 机器数据的解析与格式化与区域无关；字符串比较显式指定语义（序数或区域）；读写文本显式指定编码。
  - 理由 · 区域设置不同会让同一数据解析出不同结果。
- **MUST** `CODE-07` 解析外部数据用安全默认值：XML 禁止 DTD 和外部实体；不对外部数据使用不安全的反序列化（`BinaryFormatter`、`pickle`）；schema 不加载远程引用。
  - 理由 · 防止 XXE 和不安全反序列化漏洞。
- **SHOULD** `CODE-08` 错误用具体类型，保留原因（内层异常、`raise from`、`cause`）；不抛出通用基类或字符串。
- **MUST NOT** `CODE-10` 可变的全局或静态状态；进程级设置只在启动时设置一次。
  - 理由 · 全局可变状态让测试互相干扰并引发并发错误。
- **SHOULD** `CODE-14` 构建、生成与发布自动化用项目主语言写在 `build-tools/`，一个入口；不新增零散的 shell、PowerShell、batch 脚本。

## <a id="code-concurrency"></a>并发

具体工具见语言附录，隔离不稳定的组件见 [2.2](02-architecture.md#arch-isolation)。

- **MUST** `CODE-15` 共享的可变状态有明确的所有者和保护方式：只归一个线程或队列，或者用写明的锁、线程安全的数据结构或原子操作保护。优先用不可变数据和消息传递。
  - 理由 · 数据竞争会产生随机的错误结果，很难复现，测试也常常抓不到。
- **MUST** `CODE-16` 持有阻塞锁时不跨 `await`，不调用传入的回调，不做网络、设备或进程间调用；本地文件的短写入（审计、状态文件）除外。要串行化这些长操作时，用异步锁或单一队列（`ENG-05`、`ARC-06`），等锁有时限（`ERR-14`）。需要多把锁时顺序固定。
  - 理由 · 否则会死锁，软件挂起时也查不出原因。
- **MUST** `CODE-17` “先检查再动作”要是一个原子操作：文件用独占创建，读改写加文件锁或比较版本（原子替换只防半写，`ERR-21`，不防丢更新）；数据库用事务或条件更新；内存状态放在同一把锁或同一个队列里。多方并发修改同一份数据时不静默丢掉别人的修改；最新值覆盖是设计本身时（如当前值、缓存）写明。
  - 理由 · 检查和动作之间的空隙会让状态被别人改掉，造成重复写入或覆盖别人的修改。
- **MUST** `CODE-18` [M+] 长期运行或接收外部请求的程序，队列、并发任务数和连接数有上限。满了就有时限地等待、拒绝，或按写明的策略丢弃（`VIS-13`、`ENG-05`），并有计数或日志。
  - 理由 · 无上限的队列和任务会耗尽内存，把一次变慢变成一次停机。
- **SHOULD** `CODE-19` 后台任务有所有者：谁启动、怎么取消、退出时等待还是放弃都写明；程序退出时按顺序停止。
- **SHOULD** `CODE-20` 假设只有一个实例运行时写明，并在启动时检查（`DSK-05`）。
