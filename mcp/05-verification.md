# 验证层

> **要点** 单元测试证明工具能工作，Agent 评测证明模型会用，实机核对证明目标真的这样运行。三者不能互相代替。

## <a id="ver-contract"></a>规格与契约

- **SHOULD** `VER-01` 新工具和契约变化先写[工具规格](templates/tool-spec.md)，审查后再实现，规格保存在仓库中。名称和参数发布后就很难改。
- **MUST** `VER-02` 工具契约包括名称、描述、输入输出 schema、注解和服务器说明，全部进入快照测试。快照只由正式工具更新，差异逐项说明，从不自动接受。
  - 理由 · 契约悄悄变化会让客户端失效，也可能是工具投毒。
- **MUST** `VER-03` 1.0 起，同一主版本内只做增量（新工具、新可选参数、新字段、新错误码）。破坏性变化升主版本，并附新旧对照表。
  - 理由 · 破坏性变化会让现有客户端和提示词失效。
- **SHOULD** `VER-04` 弃用的工具和参数在目录和用法中标注替代项和计划移除的版本，调用时给出弃用警告。
- **MUST** `VER-05` 用测试核对每个工具的安全级别、注解和审批行为彼此一致。
  - 理由 · 级别和审批行为不一致时，写工具可能绕过审批，而且没有人发现。

## <a id="ver-tests"></a>测试

- **MUST** `VER-06` 默认测试不连接真实目标，用假的适配层或本机夹具；除适配层工程外，生产代码能在没有目标软件时构建和测试。
  - 理由 · 依赖真实目标的测试慢、不稳定，也可能写坏工程。
- **MUST** `VER-07` 涉及写入的改动有失败路径测试：审批被拒绝、超时或不可用；计划过期；结果未知后暂停且不重放；路径越界；凭据去敏；适配层超时、崩溃和坏回复；客户端重发；写入派发后取消；崩溃后重启恢复。
  - 理由 · 这些路径平时走不到，出事时才走，不测就等于没有。
- **SHOULD** `VER-08` 检查面向模型的文本：示例符合输入 schema，描述和示例只提到已注册的工具，文本为英文（项目数据除外）。

## <a id="ver-real"></a>实机核对

- **MUST** `VER-09` 依赖目标的行为有实机核对清单，只在一次性项目上运行。结果记入台账：目标版本、日期、项目、结果；没跑的写 `NOT RUN`。发布说明附未验证清单。
  - 理由 · 防止发布说明声称没有验证过的能力。
- **SHOULD** `VER-10` 每个工具和动作至少一条示例，参数经实机核对，或写明验证范围（例如“离线预览，原生执行 NOT RUN”）。示例只在一处源数据中维护。
- **SHOULD** `VER-14` 未经实机验证的行为在每个相关结果中带警告，不只写在发布说明里。

## <a id="ver-evals"></a>Agent 评测

- **SHOULD** `VER-11` 维护 Agent 评测任务集：任务取自真实需求；结果由程序验证，不看模型自述；记录工具调用次数、token、错误比例和完整轨迹。
- **SHOULD** `VER-12` 任务集分开发集和保留集。改进描述时只看开发集，保留集用来验收。发布前和描述改动后运行，成功率低于上一版时不发布，除非有书面说明。
- **SHOULD** `VER-13` 对抗任务覆盖项目文本中的注入内容，验证模型不会因此发起写入。

## <a id="ver-checklist"></a>新增工具清单

- [ ] 确认现有工具加可选参数不够用；采用 `VER-01` 时写好工具规格。
- [ ] 名称的动作都在词表中；描述符合 `TL-10`，用英文。
- [ ] schema 符合 `TL-14`：`additionalProperties: false`、`required`、`enum`、`default`；列表按 `TL-26` 分页。
- [ ] 安全级别和四个注解已显式登记，彼此一致。
- [ ] 写工具：显式目标身份、可预览、经审批、带 `execution`、写审计；结果未知不重放。
- [ ] 错误码在表中，`retryable` 正确，消息指导下一步。
- [ ] 项目自由文本只在数据字段中；大小在预算内。
- [ ] 注册的每个目标版本都有 API 证据；不支持的动作在调用目标前拒绝。
- [ ] 采用 `VER-10` 时有示例，写明验证范围；实机核对清单已更新。
- [ ] 契约快照已更新，差异逐项说明；失败路径有测试；采用 `VER-11` 时至少一个 Agent 评测任务。
