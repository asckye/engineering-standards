# 工程软件 MCP 开发规范

状态：**草稿 0.1**。规则已与两个在开发的项目逐条对照，还没有用新项目从零验证过。

本规范写给开发 MCP 服务的人和 AI 编码代理。检验标准有两条：模型第一次看到工具就能用对；模型出错时，真实工程不会被写坏。

## 适用范围

**适用：** 通过 MCP 连接工程软件或设备，并且能写入真实工程的服务。这类服务通常运行在用户本机或虚拟机中，一次服务一位工程师，写错的代价很高，也可能很久之后才被发现。

**部分适用：** 多租户的远程服务和纯只读的查询服务。协议层和工具设计层仍然适用；授权按 MCP 规范，写入安全层和适配层按需要取舍。

## 依据等级

每条规则都标明依据，读者可以自己判断分量。

| 标记 | 含义 |
|---|---|
| `[规范]` | MCP 2026-07-28 规范本身的要求或指引 |
| `[两项目]` | 两个在开发的项目都已完整实现 |
| `[一项目]` | 只有一个项目完整实现，另一个没有或只做到一部分 |
| `[部分实现]` | 两个项目都只做到一部分 |
| `[建议]` | 还没有项目实现，属于判断 |

“已实现”不等于“已在真实工程软件上验证”。实机验证按 [`VER-09`](05-verification.md#ver-real) 单独记录。

两个项目都做不到的规则，本版已降级或改写。下面几条仍保留为 MUST，因为它们保护真实工程的数据，或来自 MCP 规范：`PRO-08`、`PRO-09`、`PRO-13`、`WS-28`、`WS-29`、`WS-32`、`VER-09`。

`MUST`、`SHOULD`、`MAY` 的含义和优先级与[工程开发规范 0.3](../general/00-purpose.md#purpose-read) 相同。

## 和工程开发规范的关系

[通用规范](../general/README.md)仍然适用，包括代码规范、注释、易读易维护、错误处理、依赖、测试和 Git。本机运行的服务还要采用[桌面与本机软件](../desktop/README.md)中的本机软件、Windows、打包和诊断规则。

本规范取代工程开发规范 1.1 的领域 A（MCP 服务）和领域 C（工程软件自动化）。不做 MCP、但要经厂商 API 驱动工程软件的工具，也按[工程软件适配层](04-engineering-adapters.md)。本规范和 `desktop/` 不一致时（例如 `WS-34` 与 `SEC-14`、`PRO-18` 与 `SEC-17`、`PRO-19` 与 `SEC-16`），以本规范为准。服务带 WPF 审批窗口时，再加[桌面应用](../desktop/README.md)和[桌面界面](../desktop/ui.md)。规则对应关系和每处变化见[对照表](handbook-mapping.md)。

项目采用本规范时，在[项目采用文件](../templates/project-adoption.md)里写明版本和偏差，或者只写进项目 README 的“工程规范”一行。做不到的 MUST 写 ADR；已发布的名称和字段不为本规范改名。

## 目标协议

本规范按 [MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog) 编写。这次修订取消了协议会话和 `initialize` 握手，所有结果都带 `resultType`，服务端发起的请求改为多轮请求（MRTR），Tasks 移到了扩展。还在旧修订上的项目把差异登记为偏差，并写明迁移计划。

## 本版的取舍

开写时两个项目在下面几处做法不同，本版这样定：

1. **协议：** 新服务用 2026-07-28 和官方 SDK 的稳定版本。
2. **命名：** 强制词表和全服务一致，不强制某种大小写。新服务用 `<产品>_<资源>_<动作>`。
3. **结果：** 不强制统一信封。强制写工具用 `execution` 说清目标有没有被改。
4. **错误：** 错误对象带显式的 `retryable`，字段含义统一。
5. **审批结果：** 拒绝、过期和无可用窗口用不同的错误码，因为模型的下一步不同。
6. **一次性项目：** 允许普通写入免审批，但必须由服务端认定，破坏性操作仍要审批。

进程模型不统一：独立 worker 进程和目标软件内的插件都可以，本规范只规定隔离和故障时的行为。

## 术语

| 词 | 含义 |
|---|---|
| 服务 | MCP 服务进程，负责协议、策略、审批和审计 |
| 目标 | 服务操作的工程软件或设备 |
| 适配层 | 唯一调用目标 API 的代码，可能在独立进程或目标软件的插件中 |
| 写入 | 任何改变目标、设备、配置或用户文件的操作 |
| 写工具、本地工具 | 定义见[写入安全层](03-write-safety.md) |
| 预览 | 不写入，返回变更清单 |
| 计划 | 规划或预览得到的变更清单 |
| 计划哈希 | 计划内容的摘要，用来把批准绑定到这份计划 |
| 状态指纹 | 目标身份和受影响对象当前状态的摘要，用来发现批准之后的变化 |
| 审批窗口 | 人独立操作的界面：服务自己的窗口或目标软件内的对话框 |
| 一次性项目 | 服务创建和认定的 scratch 工程，可以随时丢弃 |
