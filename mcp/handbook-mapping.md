# 与工程开发规范 1.1 的对照

本规范取代工程开发规范 1.1 的领域 A 和领域 C，那两部分的原文已从仓库中移除。这张表说明每条规则的去向，“变化”一列写和 1.1 不同的地方，包括级别变化。还在引用 `MCP-xx`、`VND-xx` 编号的项目可以用它对照。

## 领域 A：MCP 服务

| 1.1 的规则 | 本规范 | 变化 |
|---|---|---|
| `MCP-01` | `PRO-01`、`PRO-02` | 目标修订改为 2026-07-28 |
| `MCP-03` | `PRO-05` | 无 |
| `MCP-04` | `PRO-08`–`PRO-10` | 协议已无会话，改为调用方每次传入的显式标识；由 SHOULD 提为 MUST |
| `MCP-05` | `TL-13` | 无 |
| `MCP-07` | `TL-05`、`TL-06` | 新服务由 PascalCase 改为 `<产品>_<资源>_<动作>` |
| `MCP-08` | `TL-05`、`TL-07` | 导入、导出的目标格式可以出现在名称中 |
| `MCP-09` | `TL-10`、`TL-11` | 示例移到用法元工具，不要求写在描述中 |
| `MCP-10` | `TL-12` | 无 |
| `MCP-11` | `TL-14`、`TL-15`、`TL-37` | `oneOf` 拆为 SHOULD；键名开放的映射除外；新增服务端校验输入 |
| `MCP-12` | `TL-08`、`TL-09`、`TL-15` | 新服务由 camelCase 改为 snake_case |
| `MCP-13` | `TL-08`、`TL-16` | 哈希格式不再单列 |
| `MCP-14` | `TL-17`、`TL-26` | 显式目标身份由 SHOULD 提为 MUST；目标由目标软件配置决定时改为在审批窗口显示 |
| `MCP-15` | `TL-19` | 可以用参数名代替 JSON 指针 |
| `MCP-16` | `TL-20`、`TL-21` | 不再要求统一信封；“一种结果结构”由 SHOULD 提为 MUST |
| `MCP-18` | `WS-17`–`WS-20` | `meta.outcome` 改为写工具的 `execution` |
| `MCP-19` | `TL-29`、`TL-30`、`TL-36`、`TL-39` | 错误码闭集由 SHOULD 提为 MUST；增加 `retryable`；最小集合不再单列“需要重置会话” |
| `MCP-20` | `TL-31` | 由 SHOULD 提为 MUST |
| `MCP-21` | `TL-32`、`TL-36` | 无 |
| `MCP-22` | `WS-01`、`WS-02` | 无 |
| `MCP-23` | `WS-04`、`WS-05` | “都能预览”保持 MUST，并限定在写工具；“默认预览”由 MUST 改为 SHOULD，只用于审批可能关闭或没有审批窗口的路径 |
| `MCP-24` | `WS-06` | 无 |
| `MCP-25` | `WS-07`、`WS-11`、`WS-12` | 错误码由 `CONFIRMATION_REQUIRED` 细分为三个 |
| `MCP-26` | `WS-13` | `IDENTITY_MISMATCH` 并入 `PLAN_STALE` 的情形，不单列 |
| `MCP-29` | `TL-25` | 无 |
| `MCP-30` | `TL-26` | 协议已无会话，游标改为绑定工具、查询条件和快照 |
| `MCP-31` | `TL-28` | “签发它的会话”改为“签发它的范围” |
| `MCP-33` | `ENG-11` | 补充一份构建支持多个版本的情况 |
| `MCP-34` | `TL-03`、`TL-04` | 完整目录也可以经档位或领域工具集访问 |
| `MCP-35` | `TL-35` | 令牌的具体期限留给项目 |
| `MCP-36` | `PRO-14`、`PRO-15` | Tasks 改为扩展，由 SHOULD 改为 MAY |
| `MCP-37` | `VER-02` | 由 SHOULD 提为 MUST |
| `MCP-38` | `TL-11`、`VER-10` | 参数没有实机核对时，可以写明验证范围 |
| `MCP-39` | `VER-08` | 无 |
| `MCP-41` | `VER-11`、`VER-12` | 成功率下降时增加“有书面说明”的例外；不再限定等级 |

## 领域 C：工程软件自动化

| 1.1 的规则 | 本规范 | 变化 |
|---|---|---|
| `VND-01` | `ENG-01`、`ENG-02` | 明确独立 worker 和插件加服务进程都可以；连接根对象和显式事务可以跨请求持有 |
| `VND-02` | `ENG-03` | 无 |
| `VND-03` | `ENG-04` | 无 |
| `VND-06` | `ENG-13` | 厂商保证二进制兼容时可以一份构建 |
| `VND-07` | `ENG-12` | 特性符号表不再单列 |
| `VND-08` | `ENG-12` | 无 |
| `VND-09` | `ENG-14` | “每次写入”限定为目标提供事务的那类操作；补充目标不能回滚时的处理 |
| `VND-10` | `ENG-18` | 无 |
| `VND-11` | `ENG-16` | 无 |
| `VND-12` | `ENG-17` | 增加附着到用户实例和目标弹确认框的情况 |
| `VND-13` | `ENG-15` | 由 SHOULD 提为 MUST，范围限定在写入、线程、回滚和崩溃相关的行为 |
| C.4 新增目标版本清单 | [新增目标版本清单](04-engineering-adapters.md#eng-checklist) | 无 |

## 通用规范和本机软件规则被本规范具体化的部分

这些规则仍然适用（`SEC-14`–`SEC-17` 在 `desktop/local-software.md`）。下表只列本规范写得更具体或不同的地方。

| 规则 | 本规范 | 变化 |
|---|---|---|
| `P-01`、`P-03` | `ENG-15`、`VER-09` | `P-01` 的范围限定在写入、线程、回滚和崩溃相关的行为 |
| `ERR-01` | `WS-20` | 无 |
| `ERR-07` | `WS-21` | 无 |
| `ERR-08` | `WS-23`、`WS-24` | 无 |
| `ERR-10` | `WS-22` | 无 |
| `ERR-14` | `ENG-08` | 无 |
| `ERR-16` | `WS-25` | 取消后可能没有回复，所以不再要求返回“已取消” |
| `ARC-12` | `PRO-20` | 无 |
| `ARC-14`、`ARC-15`、`ERR-21` | `WS-26` | `ARC-14`、`ARC-15` 由 SHOULD 提为 MUST |
| `SEC-03`–`SEC-05` | `WS-07`、`WS-08`、`WS-14` | 写明关闭开关和一次性项目两个例外 |
| `SEC-07`、`SEC-08`、`SEC-09` | `WS-29`、`WS-30` | 增加“根目录之外经审批并显示完整路径”这种方式 |
| `SEC-10` | `WS-31` | 产品自身的更新包不在此列 |
| `SEC-12`、`SEC-13` | `WS-33`、`WS-03` | `SEC-12` 限定为工具调用触发的子进程，增加启动自身界面和系统提权的例外；`SEC-13` 由 SHOULD 提为 MUST |
| `SEC-14` | `WS-34` | 对端身份核对可以换成不可预测的管道名；适配层内部协议可以容忍未知字段 |
| `SEC-15` | `PRO-17`、`PRO-23` | 由 SHOULD 提为 MUST |
| `SEC-16` | `PRO-19` | 客户端配置中的明文密钥作为剩余风险写入威胁模型 |
| `SEC-17` | `PRO-18` | 允许列表由“默认空”改为“默认不超过本端点” |
| `SEC-20` | `WS-32` | 键名规则留给项目 |
| `SEC-23`、`SEC-24` | `WS-28`、`WS-10` | `SEC-24` 由 SHOULD 提为 MUST |
| `DAT-02` | `WS-27` | 无 |
| `MIG-01`、`MIG-02` | `VER-03` | 明确从 1.0 起生效 |
| `ARC-07` | `ENG-07` | 适配层能确认结果时按确认结果报告，不再一律标为故障 |
| `P-04` | `WS-16` | 一次性项目上的普通写入可以免审批 |
| `UI-16`、`UI-17`、`UI-19` | `WS-01`、`WS-09`、`WS-11`、`WS-26` | 破坏性操作可以把“拒绝”设为默认，与第 21.8 节一致 |

界面的其他规则（例如 `UI-32` 限制 AI 打开的页面）仍按通用规范第 21 节执行。
